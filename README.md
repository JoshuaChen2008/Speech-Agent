# Live Subtitle

一个跑在 Windows 上的本地实时字幕工具，以及一套建立在字幕之上的个人 Agent。

会议在放、视频在播、你在自言自语——它把听到的话变成屏幕上一直在走的字幕，把说定的部分存到本地，然后让你可以回过头对这些内容提问、要一份纪要、要一段译文、要一个下一步计划。

> 下面讲的是这个项目**被设计成什么样**，以及为什么这样设计——不是功能清单，也不是进度表。工程上做到了哪一步、哪些门禁还没关，单独放在文末的[当前状态](#当前状态)里，两者不要混着读。

---

## 一件事拆成两半

产品由两个系统组成，它们的关系是刻意做成单向的：

**字幕系统**负责听、认、显示、保存。它是完整的、可以单独交付的东西。断网能用，没配任何模型服务也能用，Agent 整个关掉还是能用。

**Agent 系统**站在字幕的下游。它只能读字幕系统已经存好的正文，产出的一切都是另存的派生内容。它不碰麦克风，不碰识别过程，也没有资格改写一个字的原文。

之所以要划这条线，是因为这两半的失败方式完全不一样。字幕坏了你就看不见字了；Agent 坏了——超时、限流、余额不够、模型配错——你应该只是少了一个功能，而不是连字幕都停。所以设计上不允许 Agent 的任何故障向上传染。

# 第一部分：字幕与翻译

## 听见什么

每次开始，你只选一种声音来源：

- **会议字幕**：听 Windows 正在播放的声音。开会、看视频、听课都属于这一类。
- **个人听写**：听你选定的麦克风。

一次只能一种，运行中也不能中途换。想换就先停下来，再开一场新的。这不是偷懒，是因为两路混在一起之后，谁说的哪句话就再也说不清了，而后面所有派生内容都要靠"这句话出自哪里"来追溯。

识别在本机完成，不联网。

## 字幕怎么读

字幕窗是固定高度的一块，它不会因为话变多而自己长高、自己乱跑。文字自然换行，写满之后从顶上一行一行退出去，最新的内容永远在你眼前。

说话过程中不断跳变的那一行只是实时猜测，它只服务于"现在就要看见"，不会被存下来。一段话讲完、这一段关掉的时候，才会给出第一份稳定的文本——这份就是原文，从此不再改动，历史和导出默认给你的都是它。

你可以随时暂停、继续、停止。锁定之后字幕窗对鼠标完全透明，点击会穿过去落到底下的应用上，工具条仍然可以单独操作。字号、透明度、圆角和主题都能调，改完立刻看到。

## 原文、精修和译文，谁也不覆盖谁

这是整个项目最核心的一条规矩：**新产生的文本一律另存，永远不覆盖已经定下来的事实。**

- **原文**是实时识别给出的第一份稳定文本，不可变，是所有东西的地基。
- **精修**是可选的第二遍。它需要另外下载一个模型，再单独打开开关，只对之后新开的场次生效。它产出的是一份平行的精修稿，你可以随时切回原文。就算精修中途崩了，字幕照常走，停下来之后再告诉你发生了什么。
- **译文**同样是另一层。它明确记着自己译的是哪一段、哪个版本的文本，所以当正文换了版本，旧译文不会顶替上去装作是新的。翻译慢了、失败了，都不影响你读原文。

三者在界面上是分层展示的，不会混成一段看不出出处的"最终稿"。

## 之后你还能拿它做什么

结束的每一场都进本地历史，按时间排，可以翻、可以看、可以导出成 `txt`、`md` 或 `srt`。异常中断的场次同样在，不会因为没有正常停止就丢掉。

# 第二部分：Agent 链路

字幕解决"我刚才听到了什么"，Agent 解决"那又怎样"。

## 它只从一个地方拿内容

Agent 的输入只有一处：已经存好的正文。实时猜测的那行字进不来，还没定稿的尾巴进不来，没有正常结束的场次也进不来。

每次要干活之前，它先把这次能看的东西**冻住**：哪几场、哪个时间段、哪个项目、原文还是精修稿，全部先定死再开始。这样同一次请求跑出来的结果，你回头永远知道它到底看着什么说的话。有东西被排除在外——比如某场还没结束、某场压根没说话——它会明说漏了什么，而不是悄悄少算。

## 它会记住你的上下文

Agent 底下有一层个人上下文，分成两类事实：

- **会话经历**回答"某天、某场、某个项目发生了什么"，带时间范围和出处。
- **个人记忆**是更长期的东西：项目里的事实、定下来的决定、待办、你们内部的术语和叫法、你的习惯和偏好。

这些不是靠观察你怎么点鼠标攒出来的。只有你自己做过的明确动作才算数——你提的问题、你对结果的修改、你说"接受"或"不要"、你说"记住这个"或"忘掉这个"。看过、划过、停留过一律不算。自动提取出来的东西只是候选，在你确认之前不会顶掉你亲口说过的话。

每一条都能翻出来看、改、删、暂时收起来。所有内容留在本机的数据库里，不外发。

## 模型是你自己的

Agent 不绑定任何一家服务商。你在设置里保存自己的模型配置：一个可信的连接地址、一份属于它的凭据、一组你自己填清楚的模型。想配几套配几套。DeepSeek 只是初始化时给的一个空模板，你可以改、可以删，它不是默认，也不是唯一选项。

然后你只需要为四件事各挑一个模型：**默认**、**信息提取**、**摘要与总结**、**分析与规划**。没单独指定的，界面会直接告诉你它现在用的是默认那个，而不是让你以为自己配过了。

界面里不会出现内部代号、接口名或者参数名——你选的是"用哪个模型做哪类事"，不是在配一个管线。

凭据由主进程单独保管，不进配置文件、不进数据库、不进界面、不进日志、不进任何导出。

## Agent Bar：说一句话就行

正式入口是一条 Agent Bar。用法只有两步：

1. 圈定范围——当前选中的一段、某一场、一段日期、或者一个项目。
2. 用自己的话说你想要什么。

剩下的它自己判断。同一个输入框，你可以问一个问题、要一份会议纪要、要一段分析、要一个计划、要把这段话改写得正式一点、要一份译文。你不需要先知道有哪些"功能"再去找入口。

拿到结果之后，你可以直接改它、接受它、否掉它，或者对其中一条说"记住"。这些动作会回流到你的个人上下文里，下一次它就知道了。

## 会后默认什么都不做

一场会结束，默认**不生成任何报告**，只静悄悄把这场的经历记录一下。

想要自动纪要，得你自己去打开那个偏好。打开之后，每场符合条件的会议最多自动出现一次结构化纪要——不弹窗、不抢焦点、不打断你、不在图标上挂个小红点催你去读。开着不看是可以的，关掉也不会删掉之前生成的东西。

会中不做滚动摘要，不追着你实时归纳。

## 复杂的事情它自己会多走几步

简单的请求就是问一次模型答一次。碰上需要先去查点东西才能回答的，它会自己去查——比如按你们内部的叫法去个人上下文里对一下，或者把某几段原文原样调出来看看——看完再接着往下想，直到给出结果。

但这个过程是被关死的：它能用的工具只有"查"和"读"两种，全都是只读；能查能读的范围不能超出这次开始时冻住的那一份；跑多少轮、能用哪些工具，在每类任务上都是提前定死的，运行中改不了。

它没有 shell，不能起进程，不能读写任意文件，不能访问任意网址，也不能替你去外面的系统上做任何事。首版的 Agent 只生成内容，不执行操作。

任何一环没成——校验没过、超预算、工具失败、你中途取消——都不会交出半成品。取消是终态：说停就有界地收住，历史里如实记下停在哪、已经做过什么，不会给你补一个假的结果。

## 每次都留得下痕迹

每一次交互在历史里都能查到：什么时候、看的哪些内容、用的哪个模型、最后给了什么，以及它中间调了哪些工具、传了什么、拿回了什么。工具那部分默认折叠着，想看再展开。

单次交互可以导出成一份 JSON，同一次交互导出多少遍，字节都是一样的——你可以拿它去核对、归档或者交给别人复查。

不会留的东西也说清楚：模型的内部思考过程、原始事件流、以及你输入的完整提示原文。提示在跑完并提取完关键信息之后就删掉，只留一个指纹。

## 坏了也只坏它自己

没配模型、凭据失效、被限流、断网、超时、预算用完、进程挂掉——不管哪一种，字幕照常显示，历史照常保存，导出照常可用。Agent 只会告诉你它这次不行，以及你可以去做什么，不会把自己的问题变成你的问题。

---

## 关于你的数据

- 现场音频不落盘。没有录音文件，没有可回放的音频，PCM 只在有限的内存缓冲里过一遍就没了。
- 实时猜测的那行字不进数据库、不进历史、不进导出、不进诊断。
- 原文和精修稿存在本机 SQLite，个人上下文也在本机。
- 云端模型只在你自己配置并明确开启之后才会被调用；哪些文本会发到哪个服务，在开启之前会明确告诉你。
- 日志和诊断报告里不放字幕正文、设备名、文件名和本机绝对路径，也不会自己往外传。
- 卸载默认只移除程序，你的模型、配置和字幕历史留着。

## 跑起来

需要 Windows 11 x64、Node.js 和 npm。项目依赖 Windows x64 的 sherpa-onnx 预编译包，别的平台装不上。

```powershell
npm install
npm start
```

第一次用：选会议字幕还是个人听写 → 在设置里装好核心字幕模型 → 等实时识别和端点检测都就绪 → 回工具条开始。装完之后，字幕、保存和历史在断网状态下照常工作。

只想调界面、不想装模型：

```powershell
$env:LIVE_SUBTITLE_DEV_MODEL='x-asr-480ms'
npm start
```

这个开关只在开发时有效，打包出来的应用不认它。

## 测试与打包

```powershell
npm run test:core         # 契约、主进程、运行时、存储和 UI
npm run test:integration  # 跨模块用户旅程
npm run test:evidence     # 门禁与结构化证据
npm test                  # 依次跑完以上三条

npm run package:release   # 生成 Windows x64 安装器
```

自动化测试不会打开真实音频设备，也不替代实机音源、DWM 行为和干净机验收。安装器输出在 `.artifacts/release-package/`，模型不打进包里，首次使用时按固定清单下载校验。
