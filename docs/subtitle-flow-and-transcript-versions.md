# 固定高度字幕流与转写版本设计

> 状态：Accepted design · J15a/J15b/J15c 已达到确定性联合验收完成；DPI/主题/透明窗人工视觉、真实模型与音频尚未达到实机验收完成 · 2026-08-02
>
> 决策依据：[ADR 0004](adr/0004-immutable-first-pass-and-optional-refinement.md)
> 本文只冻结本次字幕溢出、原始转写和可选精修行为；右上角状态标识变色、摘要/提炼实现和音频实机验收不在本次范围。

## 1. 用户结果

字幕窗口在监听期间保持用户设定的宽高。文字写满一行后自然折到下一行；整个可见高度写满后，最上方最旧的视觉行直接退出，最新行从底部进入。界面没有横向跑马、可见滚动条、自动增高或整窗清空，用户始终看到最近且连续的一段上下文。

字幕换行只是渲染投影。它不得修改识别文本、插入持久化换行、触发 VAD/ASR 分段、提前产生 `final`，也不得改变时间戳、历史或导出内容。

## 2. 文本阶段与版本

| 名称 | 含义 | 持久化 | 默认权威性 |
|---|---|---|---|
| `partial` | 当前未关闭字幕段的完整临时识别假设；后续结果可以增长或回改前文 | 否 | 仅实时显示 |
| 首次 `final` | 字幕段关闭时产生的第一份稳定 ASR 文本 | 是，不可变 | 是，历史与导出默认版本 |
| 精修稿 | 用户为本会话主动启用精修后生成的二遍识别版本 | 是，与首次 `final` 分离 | 否，只在用户选择时显示或导出 |
| 摘要、提炼、翻译、增强文本 | 基于明确输入版本和水位生成的后续产物 | 独立保存 | 否，不得覆盖任一转写版本 |

`final` 的“稳定”只表示实时识别阶段已经结束，不保证识别内容客观正确。项目不保存现场音频，因此任何文本版本都不能宣称可还原原始声音。

## 3. 固定高度显示规则

1. 字幕流使用窗口当前可用宽度自然换行，并使用当前可用高度作为唯一视觉容量。
2. 窗口尺寸只能由用户现有的手动拉伸行为改变；字幕内容更新不得调用窗口 resize。
3. 当内容超过可见高度时，只隐藏最上方最旧的完整视觉行；底部最新行保持可见。不显示滚动条，不做横向位移，也不要求滚动动画。
4. 单条视觉行退出只改变画面。reducer/状态层仍保留当前 `partial` 的完整假设，首次 `final` 仍按完整文本持久化；但一个旧段的最后一条视觉行也完全退出后，renderer 必须只用 `{schemaVersion, sessionId, throughSegmentId}` 回报这一显示水位，主进程随即从 canonical 实时视图淘汰该前缀并为本会话保留内存墓碑。回报不得携带正文、视觉行文本或屏幕几何。
5. `partial` 回改时允许重新排版；可见区域重新取最新的连续视觉行，但换行结果不得回馈给识别器。
6. 一个字幕段定稿、下一段开始后，旧段不整窗清空，而是随着新行进入逐行淘汰。
7. 停顿或暂时没有新文本时，已有字幕继续保留。
8. 当前 `partial` 具有最高显示优先级。任何旧段或精修稿变长时，只能淘汰更旧的视觉行，不能隐藏正在识别的最新行。
9. 只要一个段仍有任一视觉行可见，它就仍在实时窗口内，精修可以替换它并重新排版；最后一行完全退出后，该段本会话内永久离场。迟到 `final/refined/translated`、精修故障回退、窗口放大、canonical state replacement 与 renderer reload 都不能令它复活。
10. reducer 的段缓存上限必须大于产品在最大窗口高度、最小允许字号下能同时显示的完整视觉行数；缓存上限只能作为内存保险，不能在视口尚未写满时提前删掉短段。若保险上限实际触发，被移除的旧前缀也必须写入本会话显示墓碑；后续高版本 `final`、canonical replacement 或 renderer reload 均不得令其复活。

这里的“逐行淘汰”是固定视口内的内容替换规则，不是用户可操作的滚动视图。

## 4. 可选精修

- 默认不启用精修，也不要求精修模型就绪。
- 精修模型缺失时，尝试开启精修不得自动下载，开关保持关闭，并显示独立的下载动作。
- 精修偏好是一个不区分 `mic`/`loopback` 的全局设置。会话开始时读取一次并冻结；修改或关闭只影响未来新会话，不改变活动会话，也不删除旧会话精修稿。
- 用户只能在没有活动会话时明确下载精修模型；模型就绪后仍保持精修关闭，必须再次明确开启。下载过程中允许明确取消并保留合法 `.part`，但应用不得因重启或网络恢复自动续传，只有用户再次点击“继续下载”才可发起 Range 请求。
- 已开启偏好可以跨应用重启保留，但启动时必须重新验证精修模型就绪证明。模型缺失或损坏时，把开关明确回落为关闭并通知用户；重新下载成功后仍保持关闭，直至用户再次明确开启。
- 启用精修时，首次 `final` 仍先作为原始版本保存。精修稿随后独立保存，不更新原始版本的正文或身份。
- 精修结果到达时，目标段若仍在字幕窗口内，自动更新该已定稿段并重新换行；当前 `partial` 不得被替换或降级为旧上下文。目标段若已经淘汰，不得重新插回实时窗口。
- 历史和导出默认选择原始版本。查看或导出精修稿必须是当前会话内的明确用户选择，并能随时返回原始版本；选择不同会话时自动重置为原始版，同一会话内翻页保留当前选择。
- 精修 worker 中途失败只降低精修能力，不能阻止实时字幕、首次 `final`、历史或导出。故障确认后，所有仍可见的已定稿段立即恢复为各自首次稳定转写并在相同固定视口内重新排版；当前 `partial` 原样保留且仍具最高优先级，已淘汰段不重新插入，后续段继续显示首次稳定转写。本会话不重启 worker、不自动补跑，运行中不弹提示、不改变右上角颜色或任何窗口 bounds。
- 会话正常停止后，工具条以不抢焦点、不改变工具条或字幕 bounds 的会话状态通知明确报告故障与整场覆盖，并提供“查看历史”；它只报告处理状态，不是字幕内容摘要，也不概括或改写字幕内容，保持到用户关闭或进入历史，开始下一会话时自动清除，应用重启不重放。详细结果持久化到历史，应用重启后仍可查看。
- 已经生成的精修稿继续保留。运行中的 worker 故障不修改全局精修偏好；只要模型仍 ready 且偏好仍开启，下一新会话可以重新尝试启动精修一次，这不等于补跑失败会话。只有应用启动时发现精修模型缺失或损坏，才把偏好明确回落为关闭。
- 历史必须按整个会话的权威数据显示“已精修 N/M 段，M−N 段使用原始版”，不得从当前详情页估算。`M` 包含全部已持久化首次稳定转写，包括停止收尾、队列限界或故障未精修段；`N` 是已有精修稿段数，`partial` 不计入。故障事实与覆盖度分别持久化/派生：`N < M` 不足以推断 worker 故障；即使 `N = M`，已确认故障仍显示“精修进程异常结束，但本次已生成 N/N 段精修稿”。`0 < N < M` 时缺失段在精修视图回退原始版并统一标记 `[原始版回退]`；该视图可明确导出，但文件名使用 `refined-incomplete`，txt/md 在文件头写覆盖提示并在回退行行首加标记，srt 在回退 cue 正文前加标记。`M > 0` 且 `N = 0` 时显示“本会话未生成精修稿”，禁用精修视图和精修导出；`M = 0` 且无故障时不显示 `0/0` 或精修结果，有故障时显示“精修进程异常结束；本会话未产生可精修的已定稿字幕”。MVP 不按技术原因筛选回退行，也不在每行展示内部故障原因。原始版查看与导出保持不变。
- 会话故障码只允许 `REFINE_WORKER_START_FAILED`、`REFINE_WORKER_EXITED`、`REFINE_DECODE_FAILED`、`REFINE_INVALID_RESPONSE`、`REFINE_INTERNAL_FAILURE`。既有会话与旧 JSONL 导入显示“未记录精修运行状态”，不得从覆盖推断故障；该说明只进入精修详情，不进入普通历史列表。
- 精修故障日志使用本地滚动 JSONL：最多 5 个文件、每个 1 MiB、最长保留 7 天，任一上限先到即清理；不自动上传。字段不得包含字幕正文、现场音频、本地路径或原始 Error/stack；手动诊断导出入口后置，不阻断当前 MVP。
- 若应用在故障发生后、正常停止前异常退出，重启后该会话标记为中断，不重放旧的工具条会话状态通知；历史仍显示已持久化故障和最终可计算的覆盖。

## 5. 验收场景

下列场景使用确定性的 CaptionEvent/DOM 旅程即可验证，不需要播放声音：

1. 长 `partial` 在固定 bounds 内从一行自然折为多行，溢出后最旧完整行退出，最新行始终可见。
2. 中文、英文、中英混排、超长单词以及 24/30/38px 字号均不产生横向滚动。
3. `partial` 回改造成换行重排时，当前完整识别假设不被截断，且不会产生 `final`、持久化写入或窗口尺寸变化。
4. `final → 下一段 partial` 连续进入时，旧段逐行淘汰；停顿期间字幕不自动清除。
5. 存储拒绝 `partial`，只把首次 `final` 纳入权威原始转写；历史与 txt/md/srt 默认导出原始版本。会话 A 明确选择精修版后，同会话翻页继续显示精修版；切换到会话 B 时显示与导出都自动回到原始版。
6. 精修默认关闭且不阻塞核心模型 ready；缺少精修模型时点开关不产生下载请求、开关仍关闭，并能继续完成字幕与历史旅程。
7. 精修模型下载中明确取消后，网络停止且合法 `.part` 保留；应用重启保持 fetch=0，只有再次点击“继续下载”才用 Range 续传。取得 ready 后开关仍关闭；再次明确开启才使下一会话启用精修。
8. 同一个全局精修偏好对随后新建的 `mic` 或 `loopback` 会话生效，活动会话内冻结。关闭后，旧会话的精修稿仍可查看和导出，以后的新会话只使用原始版。
9. 精修开启时，迟到精修自动更新仍有任一视觉行可见的已定稿段；最后一条视觉行已经退出的段由 renderer 与 canonical fold 共同记为淘汰，迟到 `final/refined/translated`、故障回退与 reload 都不得复活；当前 `partial` 的正文和显示优先级不变，字幕 bounds 不变。
10. 产生若干精修稿后精修 worker 失败时，所有仍可见的已定稿段立即恢复首次稳定转写并重新换行；当前 `partial` 逐字段不变，已淘汰段不复活，后续段继续显示首次稳定转写。会话继续且不重启/补跑；运行中不弹精修提示、不变色、不改变窗口几何。
11. 上述会话正常停止后，工具条在现有 bounds 内显示一条不抢焦点的会话状态通知和“查看历史”；该通知只报告处理状态，不被误写为字幕内容摘要，也不概括或改写字幕内容。历史在重启后仍保留故障事实与覆盖。运行故障不修改全局偏好；模型仍 ready 且偏好仍开启时，下一新会话只重新尝试启动一次。
12. 用 205 个已持久化首次 `final`（包含停止收尾、队列限界和故障未精修段）、其中 125 段有精修稿的终态会话验证：任意 50 条详情页都显示同一整场“已精修 125/205 段，80 段使用原始版”，翻页不能改变或自行推算覆盖数。
13. 当终态会话 `M > 0` 且 `N = 0` 时，历史显示“本会话未生成精修稿”，精修选择与精修导出均禁用，只能查看和导出原始版。
14. 当 `0 < N < M` 时，不完整精修导出使用 `refined-incomplete` 名称；txt/md 文件头含覆盖提示且回退行以 `[原始版回退]` 开头，srt 回退 cue 正文也以该标记开头，原始版导出 digest 不变；界面不提供逐行技术原因或“只看回退段”筛选。
15. 开启精修后重启应用：模型仍通过 ready 校验时保留开启；模型缺失或损坏时回落关闭并通知且不发起下载，重新下载后仍须再次明确开启。
16. 活动会话内拒绝下载精修模型；允许修改全局精修偏好，但活动会话继续使用开始时冻结的值，修改只影响下一会话。
17. 分别构造 `N < M` 但没有 worker 故障，以及 worker 故障但最终 `N = M` 的终态会话：前者不得伪报崩溃，后者必须显示“精修进程异常结束，但本次已生成 N/N 段精修稿”；两者重启后历史结果不变。
18. 空会话 `M = 0` 且无故障时不显示 `0/0`、不显示精修结果并禁用精修查看/导出；若存在故障，则显示“精修进程异常结束；本会话未产生可精修的已定稿字幕”。
19. 既有 SQLite 会话与旧 JSONL 导入只在精修详情显示“未记录精修运行状态”，普通历史列表不显示该说明，且任何 `N/M` 都不得被用来推断故障。
20. 逐一注入五个允许的精修故障码并拒绝其他值；启动时模型就绪证明缺失或损坏只验证偏好回落，不生成会话故障码。
21. 结构化日志只含固定错误码、阶段、会话内相对时点和计数，并负扫描正文、现场音频、本地路径、原始 Error/stack；轮转同时验证最多 5 个文件、单文件最多 1 MiB、最长 7 天且无自动上传。
22. 故障持久化后、正常停止前强制应用异常退出；重启后会话为中断状态，不出现旧的工具条会话状态通知，历史仍显示故障与最终派生覆盖。

音频实机测试仍用于证明真实 ASR/VAD/可选精修链路，不用于替代上述确定性布局和版本隔离测试。

- J15b 已达到确定性联合验收完成：首次 `final` 锚定、双版本读取、追加迁移与分版本导出均有回归；版本选择按会话作用，同会话翻页保留、切换会话恢复原始版。真实 packaged Electron 已执行会话 A 原始版→精修版→跨五页→精修导出，再切换会话 B 自动恢复原始版并按原始版导出。
