# 会话总结容量与内容质量验收记录

2026-10-11，本次 `summary.minutes@3` / `summary-quality@1` 范围达到**联合验收完成**。依据 SEM-F28/F33/F38/F39/F40、SEM-T04/T08、J29/J30/J31 与 ADR0021；不改变整个 Agent 产品链路的既有验收状态。[指标与摘要哈希](session-summary-quality-2026-10-11.json)没有字幕正文、思考正文或本地绝对路径；实际纪要保存在正常产品 SQLite 结果中。

原失败的直接原因是旧策略的 8,192 字节中间结果上限：两次返回分别为 8,520、13,183 字节，均在通过 JSON/Schema/来源校验后因尺寸被拒绝，零部分提交。这些记录未出现模型输出 token 上限耗尽的证据。

新建原文总结先组织话题，再撰写纪要，最后核对来源；整场冻结输入适配时三个阶段均读取原文。预算不足时才确定性分块，按连续来源顺序以 2–4 项扇入归并已核对结果。目录不限制原文核对，只有核对后的单份最终纪要可以提交。原文节点给出完整授权来源对象，归并节点只能使用已有引用；真实验证过程中发现的目录字段和来源身份错误已通过明确提示与授权对象修正，严格校验仍拒绝错误返回。

中间/最终上沿为 128/256 KiB；实际额度按已登记的九组候选在首次调用前冻结，独立执法字节、Schema、完整请求、模型能力、上下文和共享累计用量。新 DeepSeek 策略请求/响应各 4 MiB、thinking high；旧协议继续原期限与 512 KiB 保护。本次当前旧协议的三组真实运行都冻结为 64/128 KiB，且采用完整输入，不能据此推断所有模型都能取得上沿额度。

每个阶段经同一真实 Agent Loop/Pi；重试和工具后续请求都先检查增长后的载荷与剩余额度并持久预留。阶段拒绝跳步，重复回执不增加 Loop；实际请求数跨阶段和恢复共享。SQLite 追加 v33，v1–v32 SQL/checksum 保持不变；只保存政策、冻结额度、阶段、计数及计划摘要。中间正文和思考正文不持久化。新最终纪要按话题展示“主要内容 / 决定 / 待办 / 需要注意”；旧结果、旧绑定和旧恢复解释保留，导出追加 schema 7。活动运行即使暂时无法读取交互详情，也能展示权威快照中的尺寸实际值与上限。
