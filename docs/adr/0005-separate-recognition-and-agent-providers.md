# ADR 0005：识别 provider 与 Agent 模型 provider 分离

- 状态：已决定
- 日期：2026-08-09
- 决策者：项目负责人
- 依赖：ADR 0002、ADR 0004
- 补充：ADR 0011 已取代下文第 8 项对正式 Agent 首版本地 Agent 模型 provider 的要求；识别 provider、两类 provider 分离及其它决策保持不变。

## 背景

纯本地识别可以离线工作，但本机 CPU/GPU 负载可能让实时识别速度明显波动；云端识别的主要价值正是把权威识别负载移出本机。如果云端结果只能作为派生文本，它就不能解决这一问题。与此同时，云端不能成为字幕系统唯一生存路径，Agent 模型的选择也不应绑定识别实现。

## 决策

1. 识别 provider 与 Agent 模型 provider 是两套独立配置，可以任意组合本地或云端实现。
2. 每个新会话只冻结一种权威识别策略：**纯本地权威识别**，或**云端主力识别与本地降级**。活动会话内不得切换。
3. 纯本地权威识别继续采用 SEM-F21 的同源两阶段本地链路。
4. 云端主力识别仍以本地核心字幕模型资源包就绪为开始条件。正常期间由云端流产生 `partial` 与唯一首次 `final`，本地识别链路保持就绪但不持续解码。
5. 只有明确断开、稳定 provider 错误或宽松的连接存活检测失败才触发本地降级。普通延迟波动不触发切换；降级后同一会话单向使用本地识别，不自动切回云端。
6. 当前段可使用有界内存 PCM 补齐本地上下文，PCM 使用后释放，永不持久化。云端已经提交的首次稳定转写保持不可变；本地链路只继续尚未提交的内容。
7. 已确认关键词和范围在会话开始时冻结，并通过 provider 能力适配；provider 不支持时明确降级，不做会后字符串替换。
8. 两类 provider 分别通过项目自有窄接口、能力描述和 registry 接入。隔离 Agent 内核开发入口先接通一个 OpenAI-compatible 云端参考实现与确定性测试 provider，本地 Agent 模型 provider 只冻结接口；正式 Agent 首版按 ADR 0011 只闭合 Agent 模型 provider 的配置、启动环境凭据、冻结和降级，真实 DeepSeek 公网与本地 Agent 模型 provider 都后置。识别 provider 的首个产品切片继续同时保留本地权威识别并接通云端参考实现；以后增加 FunASR 一类云端识别适配器时，不修改字幕事件、会话状态或 Agent 产物契约。

## 取舍

- 相比“云端只生成派生文本”，本方案真正卸载本机权威识别负载，但需要严格处理云端断开、段边界和唯一 `final`。
- 相比“云端唯一识别”，本方案增加本地模型就绪成本，但断网或 provider 故障时仍能继续字幕会话。
- 相比云端与本地并行解码后竞速，本方案避免双份算力、结果争抢和不可审计切换；代价是故障瞬间需要有界 PCM 重放。
- 相比按延迟自动切换，本方案对短时网络抖动更稳定；代价是极慢但仍存活的连接不会自动降级。
- 相比直接把首家云服务写入业务层，provider registry 增加适配代码和契约测试，但能把后续服务差异限制在明确的外部边界。

## 未选择

- 云端识别仅作为派生文本。
- 只有云端、没有本地兜底的权威识别。
- 云端与本地持续并行并由最先返回者产生 `final`。
- 以普通响应慢作为自动切换条件，或在同一会话自动切回云端。
