# ADR 0021：会话总结的可观测运行与版本化长输入规划

> 2026-09-29 策略增量（已决定）：新建正式 Agent run 冻结 `agent-retry@1`，含首次最多五个 run attempt；同一模型请求或受控工具操作跨 attempt 含首次最多五次，执行前预留且不随恢复重置。旧 run 按既有冻结 `max_attempts` 与绑定继续。此约束与原有墙钟、请求、工具及用量预算取更严格者；局部耗尽不得触发外层重放。具体语义以 SEM-F28/F38/F39/F40 和 J30/J31 登记为准。

- 状态：已决定；P0/P1 子切片与 P2.1 预算策略为实现完成·尚未验收；P1 联合验收及其余 P2 实施待验证
- 日期：2026-09-27
- 依据：用户要求生成反馈、可终止、可定位及4–5小时极端会议支持。
- 修订：ADR 0016 §5/§9 对 `summary.minutes@2` 的预算作用域；ADR 0018 §7 对明确“生成总结”按钮的意图收敛要求。
- 保留：ADR 0001 单写者、ADR 0009 完整输入与中间正文零持久化、ADR 0013 两深模块加执行宿主、ADR 0016 同一 Agent Loop 与静态工具授权、SEM-F33 绑定不可变。

## 决策

2026-09-30补充（已决定）：新raw总结冻结独立summary-long-input@1策略，最多2个run attempt，与agent-retry@1单操作五次规则取严格者；既有无该标识的@2保持直接总结与原max_attempts。v20仅追加策略标识和幂等请求用量回执，复用v18计划摘要；中间节点沿SummaryMinutesV1并额外限8 KiB、节点来源范围。分页收集及规划副本受128 MiB总缓冲限额并分批让出执行，不新增执行框架。详见SEM-F39/F40及J31的同日登记。

1. 任务权威状态以 SQLite 为准，持久化后通知只是加速信号。前台活动详情定期校准；重载、窗口恢复、手动刷新及取消冲突重新读取权威快照。计时与模型活动分开。
2. 在模型路由之前提供持久受理身份，取消覆盖整条请求。明确总结按钮使用闭集动作和 `preset`；自然语言问题继续模型优先加规则兜底。取消与成功按事务先后裁决，已终态的取消返回原终态。
3. `summary.minutes@2` 由宿主建立一个确定性 Agent 输入计划，叶分块和归并节点均调用相同 AgentLoopExecutor。每个 Loop 的 `maxTurns=3`、`toolGrants=['search_context']` 静态不变；节点输入角色由计划指定，模型不能创建节点或决定覆盖范围。
4. 一个用户请求仍只有一个总结 run、一个模型运行绑定和一个最终交互结果。无需新 recipe ID、子任务注册表或第三方调度框架。一次 run 可以依次执行多个 Loop，宿主另以节点/实际请求数约束总执行量。十轴计数按语义合同登记的 run/attempt/Loop 作用域累计，不能每块重置工具或累计用量预算。此处明确补齐 ADR 0009 与 ADR 0016 原先未明确的结合方式。
5. 策略以 recipeVersion 和附加 policyVersion 冻结；旧 v1 绑定照旧解析，旧十轴 JSON 不改写。模型能力影响输入分块，不改变轮次、工具或模型身份。`bind()` 仍只有原 exact 四字段；接入层内部根据已登记版本选择策略，不接受调用者提供预算。
6. 分块正文与中间结果只在内存，持久内容仍只有最终结果和允许的工具审计。可留存计划摘要、覆盖计数/digest及运行诊断。崩溃后用户明确继续，从冻结原始输入整次重跑、递增 attempt；不恢复 Agent Loop 中间上下文，不制造部分纪要。
7. 当前 provider adapter 和全部 prompt/transport/schema 上限必须按同一政策核对，不能只改15KB。数值权威仅在 [语义合同增量](../semantic-contract.md#会话总结运行与长输入增量2026-09-27)。
8. 运行诊断与正式 Agent 交互导出分离：诊断不含正文，运行中也可导出；正文导出仍是用户主动、终态、版本化结果。无需上传服务。

## 取舍

增大单次上下文可减少调用，但不能保证所有用户模型能容纳整场输入；确定性分块能证明来源覆盖，代价是延迟及归并信息损失风险。覆盖完整不等于总结语义无遗漏，另需首/中/尾关键决定、后续修订、跨块待办和否定的内容质量评估。

不保存中间结果保住既有隐私边界，代价是崩溃恢复会重复请求。显式继续、有限 attempt 与跨重启剩余预算让代价可见且有界。本轮不引入持久分块缓存，未来若需要必须另行改语义。
