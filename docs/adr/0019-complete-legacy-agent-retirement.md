# ADR 0019：旧 Agent 完整退役

状态：已决定（2026-09-14）。取代 ADR 0015 第 2、3、5、8、10、11 项中的源码、隔离入口、旧表保留策略与 ADR 0017 的废弃关键词表保留策略；其余字幕独立性与追加迁移要求继续有效。

正式产品保留现行 Agent 及其正式支撑模块。旧数据不迁入新实现。历史迁移 SQL 与 checksum 不变，隔离 catalog 不能转换为正式库。

既有正式库在本轮任何迁移前以 SQLite 一致性快照备份，验证重新打开、完整性、外键、迁移身份和数据摘要。只有验证成立才追加 v10 退役迁移；所有旧对象删除、记录及版本更新同事务提交，外键始终开启。

备份创建、验证与退役失败分别分类，禁止通用 fallback 吞掉。可打开的已提交版本继续提供字幕、历史及导出，Agent 与会话删除禁用；用户重启后重新备份并重试。checksum 异常或未知更高版本拒绝打开。

备份留在私有数据库目录的 migration-backups，唯一文件名、继承权限、不上传、不进入 Git/日志/验证产物、不自动过期。它含历史正文，主库删除不会清除备份。应用完全退出后才可显式恢复，不自动覆盖后续数据。独立 MVP userData 不处理。

## 现场恢复简要步骤

只有在应用完全退出后执行恢复。先复制当前数据库文件到另一个安全位置，再从 `migration-backups/before-retirement-*.sqlite3` 选择需要的快照，复制为当前历史库路径。恢复后使用 SQLite 的 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`，并核对 `PRAGMA user_version` 与 `schema_migrations` 的版本和 checksum；检查通过后再启动应用。不要自动覆盖恢复后产生的较新数据，也不要把快照复制到独立 MVP 的 `userData`。

SEM-F14/F30、SEM-T03/T06/T08 与 J27 负责隐私、删除和验证。完整 lane、正式打包或必要审核未成立时保持实现完成·尚未验收。详见退役 change。
