# ADR 0004：首次稳定转写不可变，精修为可选派生版本

- 状态：已决定
- 日期：2026-08-01
- 决策者：项目负责人
- 局部替代：ADR 0001 中“`final/refined` 共同形成当前权威正文”的投影规则、ADR 0002 中“精修属于字幕权威事实”的边界，以及原先“实时 ASR、离线精修、VAD 三项资源共同决定字幕就绪”的约定

每个字幕段的第一次 `final` 被定义为不可变的**首次稳定转写**，也是默认历史、导出和后续能力的权威原始文本。`partial` 仍只服务实时显示，不逐版本持久化；现场音频仍不持久化，因此首次稳定转写表示“未经二遍改写的第一份稳定 ASR 结果”，不表示对真实语音的无损复刻。

精修保留为默认关闭的按会话可选能力。是否启用由一个不区分 `mic`/`loopback` 的全局精修偏好决定；会话开始时读取一次并冻结，修改或关闭只影响未来新会话，不改变活动会话，也不删除旧会话精修稿。模型供给与能力启用是两个独立、明确的用户动作：精修模型缺失时尝试开启不得自动下载，开关保持关闭并提示独立下载；用户只能在未监听时明确下载，模型就绪后也不自动启用，必须再次明确开启。下载可明确取消并保留合法 `.part`，但重启或网络恢复不得自动续传，只有用户再次点击“继续下载”才可发起网络。开启偏好只有在应用重启时精修模型仍通过就绪证明才保留；模型缺失或损坏时必须回落关闭并通知，重新下载后仍需再次明确开启。

启用后，精修结果作为独立的**精修稿**保存和展示，不能删除、覆盖或伪装成首次稳定转写。迟到精修稿自动更新仍可见的已定稿字幕段，但不改变当前 `partial`，也不复活已淘汰段。精修 worker 中途失败一经确认，字幕立即把所有仍可见的已定稿段恢复为各自首次稳定转写并在原固定视口内重新排版；当前 `partial` 原样保留、已淘汰段不复活，后续段继续显示首次稳定转写。会话继续，本会话不重启 worker、不补跑，运行中不弹提示、不改变右上角颜色或窗口几何。正常停止后，工具条以不抢焦点且不改变 bounds 的会话状态通知明确报告故障与整场覆盖并提供“查看历史”，详细结果持久化到历史；该通知只报告处理状态，不对字幕内容做摘要、提炼或改写，保持到用户关闭或进入历史，开始下一会话时自动清除，应用重启不重放。已经生成的精修稿继续保留。运行中的 worker 故障不修改全局精修偏好；模型仍 ready 且偏好仍开启时，下一新会话可以重新尝试一次，只有应用启动时发现模型缺失或损坏才把偏好回落关闭。

历史按整个会话显示“已精修 N/M 段，M−N 段使用原始版”，不能从当前分页估算。`M` 包含全部已持久化首次稳定转写，包括停止收尾、队列限界或故障未精修段；`N` 是已有精修稿段数，`partial` 不计入。覆盖与故障是两条独立事实：`N < M` 不自动表示 worker 崩溃；即使 `N = M`，已确认故障仍须显示“精修进程异常结束，但本次已生成 N/N 段精修稿”并保存在历史。`0 < N < M` 时回退行统一标记 `[原始版回退]`，允许明确导出为 `refined-incomplete`，txt/md 在文件头和行首标记，srt 在 cue 正文前标记。`M > 0` 且 `N = 0` 时显示“本会话未生成精修稿”并禁用精修视图和导出；`M = 0` 且没有故障时不显示 `0/0` 或精修结果，若发生故障则显示“精修进程异常结束；本会话未产生可精修的已定稿字幕”。MVP 不提供逐行技术原因或回退段筛选。原始版查看与导出不变。历史与导出默认仍使用原始版本，并允许用户明确切换精修版本。摘要、提炼、翻译和增强文本同样属于独立派生产物，必须声明输入版本与水位。不同状态与颜色的实时提醒后续另行设计，不阻断当前 MVP；未来方案必须由后端会话结果驱动，并同时使用文案或形状等非颜色通道，本 ADR 不提前冻结其视觉矩阵。

精修会话结果只允许五个稳定故障码：`REFINE_WORKER_START_FAILED`、`REFINE_WORKER_EXITED`、`REFINE_DECODE_FAILED`、`REFINE_INVALID_RESPONSE`、`REFINE_INTERNAL_FAILURE`；模型就绪证明在应用启动时缺失或损坏属于偏好回落，不产生会话故障码。既有会话和旧 JSONL 导入没有足够运行时证据，迁移后必须显示“未记录精修运行状态”，不得把无记录解释为无故障，也不得从 `N/M` 猜测。该说明只进入精修详情，不污染普通历史列表。

精修故障日志采用本地滚动 JSONL：最多 5 个文件、每个 1 MiB、最长保留 7 天，任一上限先到即清理；不自动上传。字段仍只允许稳定错误码、阶段、会话内相对时点和不含正文的计数，禁止正文、现场音频、路径、原始 Error/stack。手动诊断导出入口后置，不阻断当前 MVP。故障在确认时立即持久化；若应用在正常停止前异常退出，重启后会话进入中断状态，不重放旧的工具条会话状态通知，但历史仍显示已持久化故障和最终可计算的覆盖。

这一决定接受默认原始转写可能缺少标点、个别词准确率低于二遍识别的代价，以换取来源可审计、用户可恢复和派生处理不破坏原文。核心模型就绪条件因此只包含实时 ASR 与 VAD，精修模型独立按需供给；现有把 `refined` 写入字幕事实并替换 `segments` 当前投影的实现、迁移、历史、导出、模型安装和验收证据都需要重新对齐。既有 append-only 事件和历史验证记录不得删除；迁移必须保住旧 `final`，并把旧 `refined` 作为可区分的派生版本处理。
