## Codex 的源码核查

用户提出的“右上角关闭始终可见”有布局依据：[`agent.css:12`](../../src/agent/agent.css#L12) 和 [`agent.css:18`](../../src/agent/agent.css#L18) 只给 body 与 `.agent-shell` 设置 `min-height: 100vh`，没有把页面高度约束在窗口内；标题栏处于普通文档流。虽然三个面板已有 `overflow: auto`，父层仍能被内容撑高，使整页滚动带走标题栏。这是源码分析，本轮没有用长总结在实机重新复现。

| 优先级 | 调整建议 | 当前依据与复刻边界 |
| --- | --- | --- |
| P0 | 将标题栏作为窗口壳的独立、不滚动区域；只允许正文面板滚动 | 在 `html/body/#root/.agent-shell` 建立明确的窗口高度链，外层关闭滚动；`.agent-layout` 占剩余空间并允许收缩，三个面板承担各自滚动。保留原标题栏 DOM/ref 与拖动绑定。优先解决高度和滚动归属，避免只给关闭按钮加 `position: fixed` 后产生遮挡或重复预留。 |
| P0 | 关闭按钮保持单行、不被压缩；长状态消息不参与挤压 | [CSS:19–26](../../src/agent/agent.css#L19)、[标题栏 DOM](../../src/agent/agent-view.tsx#L1486)。关闭控件保留明确命中面积及 `no-drag`；标题、辅助说明和状态区域允许收缩。详细反馈放在正文的反馈区域，保留 `aria-live` 和完整信息，不能只用省略号藏住错误或恢复下一步。 |
| P1 | 明确 720 宽窗口的上下分区高度 | [窄窗规则](../../src/agent/agent.css#L115) 把生成记录放到下方，但只有 `max-height: 260px`。在受约束的页面高度内定义正文与生成记录的两行分配，均允许内部滚动。可先评估生成记录约占正文剩余高度的四分之一、上限约 160–180px；这是待评估的排版取值，不改 BrowserWindow 几何，也不隐藏记录入口。 |
| P1 | 给日期与按钮建立清楚的纵向表单布局 | [日期区域](../../src/agent/agent-view.tsx#L1494) 中 label/input 相邻排列，左栏在窄窗为 170px 且有左右 padding。日期 label 分行，输入宽度随内容区收缩；按钮保持可读。复用主题字体、表面、焦点与共享控件体系，保留原生日期选择语义和既有事件。 |
| P1 | 优先呈现总结内容，次级信息继续按现有展开层次组织 | 主要内容、决定、待办、需要注意保持既有栏目；来源保留在相关内容旁。运行详情、诊断、反馈与记忆维持各自的展示层次，不把它们堆进标题栏；取消和恢复入口在适用状态下仍可发现。空状态截图无法证明长内容阅读效果。 |

建议的分区是：

```text
标题栏：标题 / 简短状态                         关闭
--------------------------------------------------
会话范围列表    | 会话总结正文、来源、运行反馈
独立滚动        | 独立滚动
--------------------------------------------------
生成记录：默认窄窗放在下方，宽窗沿用右栏；独立滚动
```

标题栏可先沿用现有 48px 基线；任何长消息都不应让关闭按钮折行。关闭窗口与取消生成必须继续分离，关闭不发送取消。不要借视觉调整修改资格、运行快照、模型活动、记忆授权、来源导航或生成记录的语义。

## 实施前后应核对的行为

- 在 720×640、520×420 和宽窗口中，用空状态、长结果及长状态消息检查：整页不滚动；正文滚到底后标题栏和关闭控件仍在窗口内；没有横向裁切；生成记录仍能访问。
- 在运行、取消、失败与恢复状态检查：关闭不取消，取消按钮和恢复入口可发现，长反馈不挤占关闭控件，也不伪造进度。
- 用 Tab/Shift+Tab、窗口缩放、系统 DPI 和 forced-colors 检查焦点不被裁切、关闭保持可聚焦、日期控件可操作、表面与轮廓可读。
- 复用 `tokens.css` 语义层、共享选择控件和既有图标；不引入新字体、依赖、组件主题分支、字面颜色、渐变、模糊或装饰动画。
