# Agent 首版 UI/UX 设计交接

> 状态：已决定 · 2026-08-09
>
> 面向对象：接手首版 Agent 界面设计的视觉/UI 模型
>
> 文档职责：把已经冻结的产品语义转换成信息架构、状态与交互约束；不定义新的产品语义，也不作为实现证据。
>
> 权威来源：[`semantic-contract.md`](semantic-contract.md) 的 SEM-F08/F13/F15/F16/F25–F28、[`testing-strategy.md`](testing-strategy.md) 的 J20–J22、[`agent-plugin-architecture.md`](agent-plugin-architecture.md) 与 ADR 0003/0005/0006/0008。发生冲突时，以 `semantic-contract.md` 为准。
>
> SEM-F29/J23 的隔离 Agent 内核开发入口不属于本交接的正式产品 UI。它只复用现有设置页视觉 token 构建基础调试壳，不得据此宣称以下四个产品表面已经实现。

## 1. 交接目标

在不改变字幕核心体验的前提下，为首版增加四个可设计表面：

1. 设置中的权威识别策略与识别 provider。
2. 设置中的 Agent 模型 provider 与个人记忆总开关。
3. 字幕历史中的会后结构化纪要。
4. 默认隐藏、仅供开发与验证使用的调试聊天。

另需提供确认关键词的轻量管理入口。它是识别能力的一部分，不是完整个人记忆管理器。

设计目标不是把产品改造成通用聊天助手。实时字幕、字幕历史和导出必须在 Agent 系统完全不可用时继续独立工作；Agent 状态不得抢占字幕主操作，也不得让用户误以为派生文本覆盖了权威原始转写。

## 2. 必须沿用的现有视觉语言

以当前设置页为视觉基准，直接复用现有窗口壳、共享 token 和组件语法：

| 项目 | 当前基准 | Agent 首版要求 |
|---|---|---|
| 窗口材质 | Win11 Mica，带不透明回退 | 继续使用，不新建玻璃化或渐变背景体系 |
| 标题栏 | `48px` 中性标题栏，手动拖动，交互控件排除 | 设置、字幕历史、调试聊天保持同一结构 |
| 设置导航 | `176px` 左侧导航 + 右侧滚动正文 | 新增页面沿用，不另做仪表盘式首页 |
| 字体 | `Segoe UI Variable` 与共享字号/字重 token | 不引入新的品牌字体 |
| 内容组件 | 分组行、分段选择、开关、克制的主/次按钮 | 优先复用，避免大卡片套小卡片 |
| 强调方式 | 中性表面 + 少量系统强调蓝 | 强调色只表达选择、焦点和明确主动作 |
| 圆角与阴影 | 小到中等圆角、轻边框、低阴影 | 不使用胶囊标签堆叠、发光状态点或装饰性 AI 图形 |
| 主题 | 浅色、深色、高对比度、reduced motion | 所有新增状态必须覆盖四类环境 |

直接参考实现：

- `src/settings/settings-view.tsx`
- `src/settings/settings.css`
- `src/history/history-view.tsx`
- `src/history/history.css`
- `src/ui/shared/tokens.css`

设计稿应表现为“当前产品自然增加了几个页面”，而不是嵌入另一套 Agent 控制台。不要使用大面积渐变、玻璃卡片、机器人插画、对话气泡装饰、夸张空状态、无意义指标卡或大量 pill/badge。

## 3. 信息架构

```text
设置
├─ 显示与字幕                         既有
├─ 音频源                             既有
├─ 语音识别
│  ├─ 权威识别策略                    新增
│  ├─ 识别 provider                   新增
│  ├─ provider 能力与本地就绪状态      新增
│  ├─ 字幕延迟                         既有
│  └─ 确认关键词                       新增轻量入口
├─ 模型资源                            既有
├─ Agent 与记忆                        新增
│  ├─ Agent 模型 provider
│  ├─ 云服务正文发送说明
│  ├─ 个人记忆总开关
│  ├─ 会后任务说明与最近状态
│  └─ 调试聊天入口                     仅开发/验证开关可见
└─ 关于                                既有

字幕历史
└─ 所选终态会话
   ├─ 权威原始转写 / 精修稿             既有事实层
   ├─ 会后结构化纪要                    新增派生层
   └─ 增强文本                          后端闭环时再启用入口

调试聊天（独立正常窗口，正式导航默认隐藏）
├─ 已选择的终态会话
├─ 对话与受控工具事件
├─ 输入框
└─ 上下文/任务检查区
```

识别 provider 和 Agent 模型 provider 必须出现在不同分组中，名称、说明和状态也不得合并成一个“AI 服务”。音频源仍只表示 `mic` 或 `loopback`，不得与权威识别策略混为同一个控件。

## 4. 设置页设计

### 4.1 「语音识别」页面

#### A. 权威识别策略

使用现有分段选择样式，只有两个互斥选项：

- `纯本地权威识别`
- `云端主力识别与本地降级`

页面必须同时显示两种事实：

- “未来新会话”配置：用户现在保存、下次会话冻结的选择。
- “当前会话”快照：活动会话实际正在使用的策略；不可在活动会话中改写。

活动会话期间，控件可以允许用户预先修改未来选择，但必须用紧邻控件的短句明确“仅影响未来新会话”；不得让当前会话视觉状态跟随设置值跳变。

选择云端主力识别与本地降级时，显示以下信息，而非笼统的“混合识别”：

- 正常期间由所选云端识别 provider 产生字幕和唯一首次稳定转写。
- 本地核心字幕模型资源包仍必须已就绪。
- 只有连接明确失效才单向降级；普通响应变慢不会触发。
- 同一会话降级后不自动切回云端。
- 应用不保存现场音频；云端识别的数据处理范围由 provider 说明决定。

首次选择云端识别 provider 时需要清楚的确认对话框。建议主按钮为“确认并用于未来新会话”，次按钮为“取消”。对话框不得预选同意，也不得把说明藏进链接。

#### B. 识别 provider

provider 选择行只在所选权威识别策略需要时启用。每个 provider 行展示：

- 展示名称与本地/云端类型。
- 配置状态，例如“尚未配置”“已配置”“连接检查失败”。
- 关键词能力，例如“支持确认关键词”或“不支持确认关键词”。
- 最近一次非侵入式连接检查结果；不得把它包装成真实会话质量保证。

若 provider 不支持确认关键词，页面继续允许使用该 provider，但在确认关键词入口旁显示明确限制，不能静默忽略关键词。

凭据由主进程通过 Electron `safeStorage` 保存和检查。renderer 只能提交新凭据、读取“已配置/未配置”等脱敏状态，不能读取或回显既有密钥；`safeStorage` 不可用时只能使用本次进程内凭据并明确提示不能保存，凭据不得进入 SQLite、日志或报告。

#### C. 确认关键词

首版使用同一设置窗内的二级视图或抽屉式详情区，不新建完整知识库页面。入口摘要显示：

- 已启用的全局确认关键词数量。
- 当前选择的主题/项目范围数量。
- 当前 provider 是否支持关键词能力。
- “只对未来新会话生效”。
- 未来新会话将纳入哪些主题/项目范围；全局确认关键词始终单独列示。

详情至少包含三组：

1. 待确认候选：术语、实体名或别名，显示来源会话与建议范围；动作是“确认”或“忽略”。
2. 全局确认关键词：数量应保持克制；允许停用、修改或删除。
3. 主题/项目确认关键词：用户明确选择范围；允许切换是否纳入未来会话。

写作、摘要和表达偏好不得出现在此处，因为它们不能影响 ASR。自动候选不得以默认勾选、自动启用或“系统已学习”的文案制造已经生效的错觉。

活动会话另以只读摘要显示已经冻结的确认关键词集合版本与主题/项目范围。用户在此处修改未来范围时，不得让活动会话的只读摘要同步跳变。

### 4.2 「Agent 与记忆」页面

#### A. Agent 模型 provider

采用与识别 provider 相似但物理分离的分组。显示：

- `本地` 或用户配置的云端 provider。
- 当前配置状态与模型名称。
- 本地重任务的资源规则：活动字幕会话期间不启动；已运行任务会有界停止并稍后重试。
- 云端任务可以在字幕会话期间继续，但不得改变字幕状态。

首次启用云端 Agent 模型 provider 时，必须显示一次明确披露：终态会话正文可能自动发送给该服务，用于会后结构化纪要、增强文本和个人记忆提取；派生结果与个人记忆仍保存在本地。首版没有逐会话敏感排除。用户确认后才允许把该 provider 设为未来后台 Agent 任务的选择。

Agent 模型 provider 凭据同样只由主进程通过 Electron `safeStorage` 保存。renderer 只提交新凭据并读取脱敏配置状态；`safeStorage` 不可用时只允许本次进程内使用并显示“凭据不会保存”，不得写入 SQLite、日志或报告。

#### B. 个人记忆

用现有 switch 行实现全局开关，默认开启。说明文案应准确表达：

- 每个终态会话都会静默进入筛选，不代表整场正文被复制成个人记忆。
- 长期结构、会话经历记录与噪声丢弃是不同结果。
- 自动推断只形成带来源的记忆候选，不能覆盖用户明确内容，也不能直接影响 ASR。
- 所有个人记忆都保存在本机 SQLite；关闭后既有条目休眠，不自动删除。
- 关闭后，未来新会话不再读取由个人记忆产生的确认关键词；UI 必须在开关旁说明该联动。

首版不设计完整个人记忆浏览、编辑、图谱或语义搜索。页面可以显示无正文的健康摘要，例如“已开启”“已关闭，既有记忆休眠”“最近提取失败，可重试”，但不展示虚构的学习分数、人格画像或成长曲线。

#### C. 后台 Agent 任务

只做紧凑的最近状态区，不做任务运营仪表盘。三项任务分别显示：

- 会后结构化纪要
- 个人记忆提取
- 增强文本

可见状态建议统一为“等待中 / 运行中 / 稍后重试 / 已生成 / 失败 / 已取消”。三项必须彼此独立：一项失败时，另外两项仍显示自己的真实状态。运行本地任务因活动字幕会话让路时，用“字幕会话优先，任务将在停止后继续”，不要显示成模型故障。

自动重试不生成新版本；用户主动重新生成会创建新版本。UI 不需要暴露 `runId`，但历史详情和调试聊天应能显示可复制的诊断标识。

#### D. 调试聊天入口

只在开发/验证开关开启时显示“打开调试聊天”。正式打包默认隐藏，普通设置导航不保留空白入口。入口旁注明“仅用于验证 Agent 上下文与受控工具，不会进入个人记忆”。

## 5. 字幕历史中的会后结构化纪要

### 5.1 层级关系

沿用当前“左侧会话列表 + 右侧详情”结构。在右侧会话标题与导出操作下增加紧凑的视图切换：

- `权威原始转写`
- `精修稿`（存在时）
- `会后结构化纪要`
- `增强文本`（后端能力接入后）

默认仍进入权威原始转写。会后结构化纪要与增强文本必须有“Agent 派生内容”说明，并显示输入版本、水位、provider、模型和生成时间等来源信息；不得使用视觉层级暗示它们比权威原始转写更权威。

会后结构化纪要的首版固定栏目：

1. 概要
2. 结论
3. 待办
4. 风险

待办只是一段内容，不出现“执行”“同步到外部”“发送给负责人”等操作。若某栏目没有内容，显示克制的空值说明，不让模型补造条目。

### 5.2 状态设计

| 状态 | 历史详情表现 | 可用动作 |
|---|---|---|
| 尚未创建任务 | 说明该终态会话还没有纪要任务 | 创建纪要；涉及云端费用时先预览确认 |
| 等待中 | 行内状态，不遮住原始转写 | 可取消 |
| 运行中 | 局部进度反馈；不使用虚构百分比 | 可取消 |
| 稍后重试 | 显示可理解原因与下一步 | 立即重试或等待 |
| 已生成 | 展示结构化正文与来源信息 | 重新生成、查看旧版本 |
| 失败 | 保留原始转写，显示权威错误说明 | 重试、切换 Agent 模型 provider 后重试 |
| 已取消 | 不删除既有产物版本 | 重新生成 |

“重新生成”先打开执行预览，至少列出：所选会话、输入转写版本、是否调用云端 provider、预计会产生的新产物类型。确认后才创建新 `runId` 和新版本。旧版本默认折叠保留，当前版本选择必须清楚；不要覆盖式替换后让用户失去来源判断。

### 5.3 长正文与性能

- 纪要区不复制当前字幕时间线 DOM；只读取独立 artifact。
- 切换视图时保留所选会话，不重新载入整个会话列表。
- 任务状态使用后端快照或事件更新，不用 renderer 自己推断成功。
- 对长纪要使用正常文档流和章节导航，不嵌套多层滚动卡片。
- 纪要失败、provider 不可用或 Agent 被全局关闭，都不得遮蔽权威原始转写与导出。

## 6. 调试聊天

### 6.1 窗口与布局

调试聊天是独立正常窗口，复用 `48px` 中性标题栏、Mica/不透明回退、主题与键盘焦点规则。首稿可按当前设置窗 `880 × 620` 作为密度参考；若设计模型认为必须改变默认尺寸，应单独提出 layout contract request，不能只在设计稿中默改。

建议三段式布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ Live Subtitle Agent · 调试聊天                       [关闭] │
├────────────────┬───────────────────────────┬─────────────────┤
│ 终态会话选择    │ 对话 / 工具事件            │ 上下文检查       │
│ 时间、来源、状态│                           │ 输入版本与水位   │
│                │ 用户消息                   │ provider / 模型  │
│                │ Agent 回复                 │ 记忆注入数量     │
│                │ 工具请求与结果摘要          │ 任务与诊断标识   │
│                ├───────────────────────────┤                 │
│                │ 输入框              [发送] │                 │
└────────────────┴───────────────────────────┴─────────────────┘
```

较窄尺寸下右侧检查区可折叠为详情面板，但所选终态会话必须始终可见。调试聊天绝不自动跟随当前活动会话，也不允许选择活动会话。

### 6.2 对话与上下文

顶部持续显示：

- 所选终态会话的非正文标识、来源类型与时间。
- 当前输入转写版本、完整输入水位与 digest 的短显示。
- Agent 模型 provider 与模型。
- 注入的个人记忆条目数量和上下文预算；默认不展开全部记忆内容。

聊天记录单独保存在本地 SQLite，提供“清空当前线程”和“删除全部调试聊天记录”。清空动作必须二次确认。聊天内容不进入个人记忆，不形成确认关键词，也不成为会后结构化纪要的输入。

### 6.3 受控 Tool Calling

工具事件使用正文内的紧凑事件行或 disclosure 展示，不做终端日志流。用户可以看到：工具名称、用途、目标会话、状态、耗时和结果摘要；不能看到内部思维过程、隐藏提示词或模型草稿。

首版允许的工具只有两类：

- 读取类：读取所选终态会话的固定快照、当前会后结构化纪要、当前个人记忆投影和后台任务状态。
- 请求类：重新生成会后结构化纪要、重新提取个人记忆、重新生成增强文本。

请求类先显示确认面板。确认面板列出固定 recipe、目标会话、输入版本、provider、是否可能产生云端费用以及会生成的新版本；用户确认后才由 Agent 插件宿主创建一层专用子 Agent。UI 不提供任意工具名、任意提示词 recipe、`spawn_subagent`、shell、文件、数据库或网络工具入口。

### 6.4 聊天状态

- 未选择会话：输入框禁用，说明先选择一个终态会话。
- provider 未配置：输入框禁用，提供打开 Agent 设置的明确出口。
- 正在响应：保留停止按钮；停止只影响本轮调试响应或已确认任务，不影响字幕系统。
- 上下文过大：由宿主返回可展示限制；UI 不自动静默截断后假装使用了完整正文。
- 工具调用待确认：聊天可继续浏览，但同一目标任务不得重复提交。
- provider 故障：保留线程与已返回内容，显示重试或切换 provider。

## 7. 关键交互流程

### 7.1 选择云端主力识别与本地降级

1. 用户在“语音识别”选择云端主力识别与本地降级。
2. UI 要求选择并配置识别 provider。
3. UI 展示实时音频发送范围、本地核心资源就绪要求与单向降级说明。
4. 用户明确确认；设置保存为未来新会话配置。
5. 活动会话仍显示其冻结策略；下一会话开始后才显示新快照。

### 7.2 开启云端 Agent 模型 provider

1. 用户在“Agent 与记忆”选择云端 provider。
2. UI 显示终态会话正文自动发送范围、三类后台任务与“首版无逐会话排除”。
3. 用户明确确认，provider 配置保存成功。
4. 后续后台 Agent 任务在创建时冻结 provider 和模型；字幕会话不受影响。

### 7.3 确认关键词

1. 个人记忆提取形成带来源候选。
2. UI 在确认关键词详情中显示词形、别名、来源和建议范围。
3. 用户确认并选择全局或主题/项目范围。
4. UI 明确“未来新会话生效”。
5. provider 不支持关键词时保留条目，但显示能力缺失，不假装已经用于识别。

### 7.4 重新生成会后结构化纪要

1. 用户在所选终态会话的纪要视图点击“重新生成”。
2. UI 展示输入版本、水位、provider、费用/正文发送影响与新版本说明。
3. 用户确认后创建新任务；旧纪要保持可读。
4. 任务状态独立更新；字幕历史原文查看和导出不受阻塞。
5. 新产物经宿主结构校验并持久化后，UI 才切换到新版本。

## 8. 文案与语义约束

设计稿、组件名、测试说明和交接注释都应使用 `CONTEXT.md` 的规范术语。尤其注意：

| 应使用 | 不应使用 |
|---|---|
| 权威识别策略 | 识别监听模式、混合模式 |
| 纯本地权威识别 | 离线模式 |
| 云端主力识别与本地降级 | 云端唯一模式、双路模式 |
| 权威原始转写 / 首次稳定转写 | 最终字幕、绝对正确原文 |
| 会后结构化纪要 | 自动执行待办、会中总结 |
| 个人记忆 / 记忆候选 | 用户画像、系统已学会 |
| 确认关键词 | 自动纠错词、说话人关键词 |
| Agent 模型 provider | AI provider（含义不清） |
| 系统音频 / 麦克风 | 本地声音 |

用户可见文案遵循三个原则：

1. 先说影响对象和生效时间，例如“只影响未来新会话”。
2. 区分配置、运行事实和派生结果，不用一个绿色状态概括三者。
3. 不承诺“越用越准”；只说明确认关键词会在 provider 支持时进入未来会话快照，效果需要后续验收。

## 9. 可访问性与主题

- 所有状态不能只靠颜色；需要文本或图标加文本。
- 分段选择使用 radiogroup/radio 语义，开关使用 checkbox/switch 语义。
- provider 配置、确认关键词和执行预览必须有可预测的 Tab 顺序与明显 focus ring。
- 异步状态使用克制的 `aria-live`；不要让连续 token 或工具事件反复打断读屏。
- reduced motion 下取消流光、循环脉冲和非必要位移动画；普通主题也不建议使用这些效果。
- 高对比度下边界、选中项、禁用态和错误态必须依靠系统色与明确边框。
- 对话与纪要正文允许系统文本缩放，不固定高度截断关键内容。
- 确认对话框打开后正确管理焦点，取消后回到触发控件。

## 10. UI 所需后端契约请求

以下是设计必须消费的逻辑信息，不代表已经冻结具体 TypeScript 名称。实现前应由运行时/存储所有者在 SEM-F25–F28 与 J20–J22 下冻结 exactObject、IPC access policy、preload 和 renderer 四层契约。

| 逻辑快照/命令 | UI 最低需要 | 约束 |
|---|---|---|
| 识别设置快照 | 未来策略、活动会话冻结策略、provider、配置状态、关键词能力、本地核心资源就绪 | 不返回凭据；revision 单调 |
| 保存识别设置 | 策略/provider 选择与云端披露确认版本 | 活动会话不得被改写；失败回滚到权威值 |
| Agent 设置快照 | provider/模型、配置状态、个人记忆开关、云端披露确认版本、开发入口状态 | 与识别设置独立 |
| 保存 Agent 设置 | provider、记忆开关与披露确认 | 不让 renderer 持有既有密钥 |
| 确认关键词分页 | 候选、已确认项、范围、来源摘要、启用状态、provider 支持状态 | 不返回整场正文；支持稳定分页 |
| 修改确认关键词 | 确认、忽略、改词、停用、删除、范围选择 | 仅未来新会话读取新快照 |
| 会话 Agent 详情 | 三个 job 的独立状态、artifact 版本、输入版本/水位/digest、provider/模型、错误说明 | 权威原始转写接口保持独立 |
| 请求后台任务 | task type、所选终态会话、输入快照、执行预览确认 token | 自动重试沿用 run，主动请求创建新 run |
| 调试聊天快照 | thread、所选会话、消息、工具事件、上下文摘要、诊断标识 | 与个人记忆表分离 |
| 调试聊天命令 | 选择会话、发送、停止、确认/拒绝工具、清空 | 仅允许固定工具；拒绝活动会话 |

所有失败返回可直接展示的短句和稳定错误码。renderer 不从异常文本、超时长度或缺字段自行推断 provider 状态。任何“已生成”状态都必须来自持久化成功后的权威快照或命令回执。

## 11. 首版明确不设计

- 完整个人记忆浏览、编辑、图谱或向量搜索。
- 逐会话敏感标记与逐会话不进入个人记忆。
- 面向普通用户的通用 Agent 聊天。
- 第三方插件市场、插件权限编辑器或任意工具配置。
- 递归子 Agent、通用 `spawn_subagent` 或内部思维过程查看。
- 自动执行会议待办、发消息、写日历或调用外部办公服务。
- 活动会话内切换权威识别策略、识别 provider 或确认关键词快照。
- 因普通网络变慢在云端与本地之间来回切换。
- FTS5、图数据库、向量数据库及相应管理界面。

这些项目不要以禁用按钮或“即将推出”卡片占据首版页面；只在确实需要解释边界的帮助文案中出现。

## 12. 设计交付物

接手模型应交付：

1. 设置页“语音识别”和“Agent 与记忆”的浅色、深色主稿。
2. 确认关键词二级视图：候选、已确认、provider 不支持、空状态和失败状态。
3. 字幕历史纪要视图：等待中、运行中、已生成、失败、旧版本选择。
4. 云端识别与云端 Agent 两种不同披露对话框。
5. 调试聊天主界面、工具调用待确认、工具运行、provider 故障、未选择会话状态。
6. 高对比度、键盘 focus 与 reduced motion 说明。
7. 使用现有 token/组件与确需新增 token/组件的差异清单。
8. 需要后端新增的 contract request 清单；不得用前端 mock 状态替代缺失契约。
9. 若改变任何窗口默认尺寸、标题栏或导航宽度，单独给出 layout contract 数值、理由和窄窗策略。

设计验收以“能清楚区分字幕事实、识别配置、Agent 派生内容和本地个人记忆”为核心。视觉精致度不能以模糊这些边界为代价。
