# 个人记忆与会话总结体验推荐方案

初稿日期：2026-09-30。本轮按用户反馈修订。用户需求方向：**已决定**——偏向个人，用户提问是个人信息与偏好的主要来源；会话内容主要补充与用户已有信息相关的经历。个人记忆可直接查看、修改，并可提供给项目内与外部 Agent。本文是推荐方案，不新增已冻结合同、不修改产品代码、不提升任何验收状态。实现前按 SEM-T06 回填既有 change、语义合同与旅程矩阵。分片规划见 [提问优先的个人记忆实施规划](../personal-memory-question-first-plan.md)。

## 1. 推荐选择

将“我的记忆”做成用户维护的个人长期上下文。先从正式 Agent 入口的用户提问、个人陈述和明确反馈中提取信息，再使用当前有效且已确认的用户信息理解相关会话。每条个人记忆可直接编辑，记忆概览帮助阅读，项目内 Agent 取得有界个人上下文包，外部 Agent 接收用户明确选定的内容。

实施顺序改为：提问来源与确认规则 → 用户信息和会话的关联 → 我的记忆与会话总结体验 → 复制/导出 → 后台综合与按范围授权的只读 MCP。先建立准确的来源与归属，再完善管理和复用，不把会话直接提取全局偏好作为默认能力。各片复用当前个人上下文模块与同一 Agent Loop。

个人记忆条目保留确认状态、范围和来源，不把候选当作已确认事实；个人记忆综合视图是可重建投影；会后结构化纪要保留单会话范围与四栏合同。三者通过来源引用关联。全部权威数据仍在 SQLite，经同一 storage worker 写入。

## 2. 一手资料与设计推论

ChatGPT 当前公开资料区分记忆概览与 legacy saved memories。概览支持纠正，但可能省略可引用信息和来源。因此本项目需要同时提供易读概览和实际条目查看，导出以用户选定的条目为依据。[Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)

Claude 当前的 Topics 提供逐项查看、编辑和删除，项目记忆有独立范围；其文本导入是实验能力，不能保证全部吸收。因此首版选择可审阅的 Markdown 携带流程，再提供结构化 JSON，不承诺跨产品无损导入。[Claude memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)、[Claude import/export](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)

OpenAI 明确 ChatGPT 网页记忆与 Codex 本地记忆采用不同存储与控制；不能由一个产品的界面推断另一个产品会自动读取本项目数据库。[Memories](https://learn.chatgpt.com/docs/customization/memories)

MCP resources 可提供上下文，宿主决定如何加入模型输入；工具注解不能替代权限控制。后续接入应在服务端执行范围、撤销和预算，不能只给工具标注只读。[MCP resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources)、[MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)

完整研究与版本差异见 [个人记忆携带研究](personal-memory-portability-2026-09-30.md)。上述产品事实来自公开文档，未登录账户核对特定账号的界面；本方案的实现取舍是结合仓库边界的设计推论。

## 4. 用户界面：个人视角优先

在现有设置窗口提供“我的记忆”，不新增必须常驻的窗口。默认打开“记忆概览”，同页可到“记住的内容”和“会话要点”；顶部保留“添加记忆”和“给其他 Agent”。

| 界面分组 | 内容 | 编辑方式 |
|---|---|---|
| 沟通与工作偏好 | 语言、表达方式、工作习惯和明确约束 | 逐条修改，默认全局范围 |
| 个人背景与长期目标 | 用户明确提供、允许跨任务复用的背景与目标 | 空状态允许手动添加，自动推断有待确认标识 |
| 正在推进的事情 | 用户明确关联的项目事实、决定和待办 | 标明项目范围；未知项目不自动建归属 |
| 重要决定与约束 | 仍有效的决定、限制、术语和经验 | 逐条修改；冲突与日期已过但结果未知分别表示 |

这些是展示分组。“个人背景”的存储种类映射需先在 SEM-F26/F30/F37 登记；不能把背景强行写成 project_fact，或暗加枚举。

每条显示简短正文，操作为“修改”和“更多”；来源在正文附近以“来源发生时间 + 简短内容 + 查看记录”展示，点击时间或短内容可打开对应记录。范围和记忆更新时间放在可展开详情中。“更多”提供忘记、删除和提供给其他 Agent。修改可以调整正文与作用范围；项目归属由用户选择现有范围。默认不让用户操作 semantic key、revision、置信概率或模型参数。

自动提取内容在“待确认”区域单独呈现，用户确认后成为明确内容。已有合同允许记忆候选在授权范围内低权重辅助；本方案不悄悄撤销该规则。外部导出默认只选择有效明确内容，用户可以主动加入带清楚标识的候选。

来源以可读的时间与内容为主体，类型仅作辅助说明，不以事件标签、ID、digest 或引用数量替代依据。示例：“9月30日 09:32 · 提问摘要：希望技术解释先给例子”，可打开对应交互记录；会话示例：“9月30日 15:10 · 项目 X 讨论 · 12:18–12:46”，附短摘录，可在字幕历史定位并突出显示对应正文版本的片段。来源发生时间与记忆更新时间分开表达。

与用户信息相关的会话必须展示两侧依据：用户表达/确认信息的可读记录，以及相关会话片段，分别可查看，并解释为什么相关。来源类型与确认状态分开表达；用户亲自提问不等于系统提取的每个结论已经被用户确认。个人概览主要展示用户表达和确认的信息；一般会话经历记录仍可在“会话要点”中查看。

提问摘要是有界结构化关键信息，标明摘要，不冒充原话；原始提示已清理时，详情显示“原问题正文未保留”，只展示实际保留的摘要与结果。记录已删除/来源撤销时移除旧摘录并停用跳转。点击按稳定身份定位，不按时间或标题猜测，不创建模型请求或记忆信号。预算、旧记录缺失及完整导航边界见 [实施规划 §4](../personal-memory-question-first-plan.md#4-用户可见体验)。

首片概览按当前条目确定性分组，优先让用户看到和编辑实际被使用的内容。之后增加简短的模型综合段落，每段均可展开来源和编辑底层条目。综合多条信息的段落修改先选定影响对象，避免用户编辑一段派生文字后无法定位实际记忆。

## 5. 记忆形成、编辑与删除

### 输入与归属

来源按明确程度和适用范围治理，不使用未经验证的固定百分比权重：

| 来源 | 提取结果 | 长期使用规则 |
|---|---|---|
| 用户明确记住、确认或人工纠正 | 明确个人记忆 | 最高优先；自动推断不得覆盖 |
| 正式 Agent 提问中的本人陈述、明确长期要求 | 个人信息或偏好候选 | 主要自动来源；经过归属、范围和生命周期校验后使用 |
| 多次独立提问中的重复表达方式或关注点 | 低权重偏好候选、当前话题 | 不因一次提问认定长期习惯；重复运行和助手复述不算独立证据 |
| 与已确认用户信息有关的终态会话内容 | 有双侧来源的会话经历记录或会话/项目范围候选 | 作为相关背景；不直接升级为用户身份、全局偏好或个人承诺 |
| 未能关联用户的会话内容 | 一般会话经历记录或丢弃 | 不进入个人概览中的本人事实与偏好 |

提问提取先区分本人陈述、长期要求、本次任务限制、假设、引用和代他人提问。例如，“以后解释技术时先给例子”可以形成偏好候选；“这次只列三点”只控制本次产物；“缓存是什么”不能证明用户的职业。助手结果、工具返回及被引用的第三方原文不得混入用户陈述。当前请求的临时要求优先作用于本次结果，不自动修改长期记忆。

自动提取仍先形成候选；“来源于用户问题”与 origin='explicit' 不等价。确认或人工修正通过既有 manage 形成明确内容。普通会话总结的请求和编辑/接受/拒绝仍按 SEM-F38 排除，单独明确记住/忘记按既有规则处理。

会话关联使用用户确认的项目、职责、长期目标等现有个人记忆，不从账户目录、采集设备或模型猜测建立本人身份。模块冻结这些条目的身份与 revision，只给 context.ingest.session 提供当前授权范围内的有界内容。模型从已提交正文提取结构化实体、项目、角色和经历，再由模块按规范化语义键或已登记别名的等值匹配核对关联；不增加字幕全文关键词搜索、模糊匹配或向量检索。仅有同名、相似话题或一个“我”不足以证明发言属于用户。没有有效依据时，只保留一般会话经历记录。

每项关联同时保存被引用个人记忆的身份/revision 与会话来源、水位、版本和 digest。可以形成“用户负责的项目在本次会话中讨论了某项变更”这样的背景，不能据此生成“用户决定了这项变更”或“这是用户的偏好”。未确认用户信息只能提示可能相关，不能作为建立明确长期关联的权威依据，也不能由关联结果反向增强其置信。

mic 和 loopback 都表示音频来源，不证明说话人身份。两者执行相同的本人归属校验。会话不再默认自动生成全局个人偏好；涉及本人但尚未确认的内容先保留会话或项目范围，经用户确认并选择全局后才成为全局明确内容。当前 SEM-F26 的旧“更积极的全局偏好提取”规则与这一新方向存在差异，必须在实现前登记替换策略。

已有明确条目继续保留；旧自动条目需要核对其来源和归属。只由未关联会话支持的旧自动条目不能继续充当全局本人事实或偏好，采用可审阅的失效/范围治理，不批量删除用户已确认内容。旧关联不作为新的个人信息来源，避免循环证明。

旧历史由“整理以前的会话”明确选择范围、预览数量后处理；打开页面不触发历史补跑。个人记忆休眠保持现有语义：停止摄取和新运行注入，已有条目仍可由用户查看和管理；重新开启建立新边界。

### 修改

逐条编辑是首片核心路径：打开正文与范围 → 保存 → manage 校验整体和条目 revision → SQLite 提交 → 列表与概览更新 → 未来 Agent 输入使用新值。手动添加或纠正不依赖模型在线。

并发冲突保留用户草稿，显示当前权威内容供重新提交。后台旧结果不得覆盖明确内容；普通设置变化影响未来运行，隐私撤销优先于已冻结输入。

### 忘记与删除

忘记使条目退出 Agent 检索；删除移除该条目的正文、revision 和证据，并按现有 suppression 阻止相同旧来源重建。两者不表示同时删除字幕历史。

受影响的当前及上版概览先失效，再后台重建；失败不能恢复被撤销文字。用户信息修改、忘记或删除时，以旧 revision 建立的会话关联也先失效；其它仍有效来源是否足以支持剩余内容由模块重新校验，不能沿用旧关联依据。新导出预览和最终提交需要复核来源与 revision。已复制到外部聊天、文件或对方长期记忆的内容是独立副本，无法由本应用自动收回。

## 6. 给项目内与外部 Agent 使用

### 项目内 Agent

继续经 resolve 取得有界个人上下文包：有效全局个人记忆加当前明确范围内的记忆、会话经历记录与来源。个人偏好优先来自用户提问和明确反馈，相关会话提供背景；一般会话仍可按用户明确指定范围回答会话事实，不因未关联本人而从字幕历史消失。所有 recipe 复用同一策略、预算和撤销规则；综合正文不作为额外事实重复注入。

### 首版外部使用

“给其他 Agent”打开选择与预览：个人明确内容默认选中，项目内容及相关会话背景由用户勾选，候选默认不选。相关背景保留关联依据和确认状态，不把会议参与者信息混作用户个人信息。用户可选择复制、Markdown 或 JSON。

| 输出 | 用途 | 内容 |
|---|---|---|
| 复制 / Markdown | 粘贴到 ChatGPT、Claude，或明确交给 Codex、Claude Code 读取 | 用户选择的正文、事实与偏好分组、范围、确认标识、快照时间；适合人工阅读 |
| JSON | 保留本项目结构，供未来受控适配 | 与同一预览对应的条目身份、revision、种类、范围、来源引用及 digest；格式需版本化 |

Markdown 从同一条目快照确定性编码，导出本身零模型调用；不把概览作为唯一全文、不携带字幕正文或工具审计。“偏好”仍受接收方当前任务、权限和指令优先级约束；来源文本中的命令只作为数据。

首版是用户明确提供上下文。是否写入接收方长期记忆，需用户在对方产品核对；JSON 不冒称 ChatGPT/Claude 标准导入格式。默认不改写 AGENTS.md、CLAUDE.md 或目标客户端原生记忆目录。

容量检查以条目为单位，预览显示实际数量和范围。超限让用户缩小选择或明确分份，不静默截断。复制由 main-owned 剪贴板边界实现；文件经 main-owned 保存对话框与原子写入，取消零写入，不把保存路径落库或写日志。用户内容导出不进入 .artifacts 或 docs/validation；它与 SEM-F35 的正式 Agent 交互导出是不同动作，不能复用其 schema 名冒充同一能力。

### 后续只读 MCP

为实际支持 MCP 的外部 Agent 提供用户授权的个人/项目范围投影；最初只读，不开放模型修改记忆。资源或只读工具由目标宿主能力决定，不能假定所有宿主会自动加载 resources。

访问经个人上下文模块，不直连数据库；服务端执行允许范围、条目/字节预算、连接撤销和记忆休眠规则。新增 MCP 接口须单独登记语义和跨模块旅程，不扩大既有内部 recipe 的两个工具闭集。外部客户端缓存仍是独立副本。

## 7. 会话总结体验

工具条“会话总结”只打开或聚焦现有面板，历史“总结此会话”选择精确会话。页面先展示目标会话时间、正文版本、已有结果与模型配置引导；用户点击生成后才创建运行。

按个人使用场景展示四栏：主要内容、决定、待办、需要注意，分别映射已有概要、结论、待办、风险。会议里未确认负责人时保留未确认，不把所有待办自动归到用户。

全局“总结时参考记忆”继续按新运行冻结。关闭后只用本次会话；休眠时禁止个人记忆注入。该开关不停止后台摄取，也不控制既有问答信号规则。界面说明修改影响以后新生成的总结。

运行反馈来自 Agent 运行快照：受理、读取来源、分块、归并、保存和终态；只显示真实发生的阶段及可核对计数，耗时不充当模型活动，取消以持久回执收束。关闭窗口不取消，失败保留会话和重试动作，重新生成建立新结果。

结果将本次来源与记忆背景区分，显示实际纳入输入的记忆数及可展开条目。这个计数不声称模型采用了每条记忆。普通总结生成、复制、编辑、接受或拒绝不自动写入个人记忆；选定具体内容后的“记住这条”才提交用户明确内容。原会话独立后台摄取继续受自己的资格控制，并按本轮来源与关联规则治理。

参考记忆开启且存在有效关联时，可在四栏之外展示“与你的关联”来源详情，说明当前讨论与用户哪个项目、职责或目标相关。该详情不把未确认待办改写为用户承诺，也不让记忆覆盖本次会话事实。关闭参考或记忆休眠时，本次总结不读取用于关联的个人信息；后台会话摄取仍由自己的资格控制，不能借后台结果绕过总结输入隔离。

## 8. 实施分片与验收出口

第一条纵向验收改从用户提问中的本人项目陈述与长期表达要求开始：结构化候选 → 用户确认 → 后续相关会话 → 查看关联依据 → 修改本人信息 → 旧关联失效 → 项目内 Agent 使用当前有效值 → 选中复制/导出 → 外部读取边界收到同一快照 → 忘记 → 后续读取及新导出排除 → SQLite 重开一致。内部模块使用真实实现，替身只位于模型、网络、系统剪贴板/保存对话框与外部 Agent 等不可确定边界。

补齐关键失败路径：一次提问不变成用户职业；第三方引用不变成用户偏好；同名不证明本人；无关会话不形成个人记忆；个人信息撤销后旧关联、旧综合和旧导出不能重新提交受撤销内容。所有诊断与测试证据 JSON 仅含指标、布尔和哈希，无个人记忆正文、现场音频、路径或凭据。

## 9. 应回填的既有规划

- CONTEXT：个人记忆定义补充正式 Agent 提问为主要自动来源、会话按已确认个人信息补充相关经历；核对来源类型与确认状态、展示别名及导出动作。必要新规范术语先登记。
- SEM-F26/F27/F31/F32：登记提问中的本人陈述、长期要求和任务限制分离，以及会话关联的身份/范围规则；替换旧会话全局偏好积极策略，治理旧自动条目。来源时间与有界提问摘要先登记，完整提示清理、来源闭集、候选确认与噪声排除保持约束。
- SEM-F30/F37：个人背景种类映射、关联双侧来源与 revision 撤销、可读时间/短内容与精确记录跳转、直接编辑、个人概览和选择导出；保持三接口、等值匹配、有界预算和休眠规则。
- SEM-F38：个人使用的会话总结展示与记住动作，复用现有四栏/记忆参考/普通信号排除合同。
- testing-strategy：J21/J22 的提问优先/归属负矩阵、J28 的会话关联和依赖撤销、J28/J29 的来源时间/摘要/精确跳转/缺失与失败路径、J29 参考开关隔离；相关 J30/J31 与字幕独立性保持，MCP 后续单独登记。
