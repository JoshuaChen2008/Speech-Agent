# 个人上下文 Agent 设计对齐版

> 性质：设计对齐记录；已同步到 `docs/semantic-contract.md` 与 `docs/testing-strategy.md`，尚未进入正式实现。
>
> 日期：2026-08-29

## 1. 目标重新定义

本项目不再把 Agent 主要理解成“对一段字幕做一次问答或会后后处理”，而是把它设计成一层可长期积累的**个人上下文 Agent**：

```text
持续捕捉已提交的文字与正式 Agent 交互
        ↓
自动形成个人记忆与会话经历
        ↓
按需回顾、分析、解释和规划
        ↓
其他 Agent 读取相关个人上下文，形成稳定的个人风格
```

Typeless 主要借鉴入口和交互理念：当前上下文、紧凑 Agent Bar、一次自然语言意图、低认知负担。项目自身的核心差异是：把多次会话积累为可追溯的个人记忆，并在未来问题中复用。

这不是通用聊天 Agent，也不是把所有聊天记录无差别变成知识库。

## 2. 数据与产物分层

| 层级 | 定义 | 主要用途 |
|---|---|---|
| 权威原始转写 | 字幕系统保存的不可变文字事实 | 作为所有后续处理的来源 |
| 会话经历记录 | 某个会话、某段日期或某个主题发生了什么 | 时间线回顾、跨会话分析 |
| 个人记忆 | 用户长期偏好、表达风格、项目事实、决定、术语和习惯 | 被其他 Agent 按需复用 |
| 分析报告 | 根据选定字幕、会话经历和个人记忆临时生成的版本化产物 | 回顾、总结、趋势和原因分析 |
| 规划建议 | 根据个人记忆、历史经历和当前约束生成的计划草案 | 行程、任务安排和下一步建议 |

最重要的区分是：

- **会话经历记录**回答“发生了什么”；
- **个人记忆**回答“这个用户长期是什么样”；
- **分析报告**回答“基于这些记录可以得出什么”；
- **规划建议**回答“接下来可以怎么做”。

分析报告不能只依赖个人记忆，否则会丢失具体时间和证据；个人记忆主要用于让报告和规划更符合用户。

## 3. 新的 Agent 链路

```text
字幕提交边界
        ↓
会话经历提取 ───────────────┐
        ↓                  │
个人记忆提取与合并          │
        ↓                  │
个人上下文投影              │
        └────→ 上下文解析模块 ←──── 当前选区 / 会话 / 日期范围 / 项目
                         ↓
               固定 recipe 的 Agent 执行宿主
                         ↓
       Agent 模型接入层 → OpenAI-compatible 多档案 / model
                         ↓
          问答 / 分析报告 / 规划建议 / 改写 / 翻译
```

现有 memory schema、来源证据、revision/suppression、SQLite 后台任务、utility 隔离和幂等恢复可以作为迁移素材；旧 `MemoryReader`、`AgentPluginHost`、三项会后任务和调试聊天产品外壳不再作为新架构基础。它们应由统一个人上下文模块和固定 recipe 的 Agent 执行宿主替换，而不是继续叠加。

## 4. 记忆形成方式

个人记忆不需要逐条等待用户确认。建议采用“自动写入、低权重起步、持续合并”的方式：

1. 从已经提交的字幕、正式 Agent 交互及其闭集交互记忆信号中提取结构化记忆候选。允许的交互信号只有提示、明确编辑、接受、拒绝、“记住”和“忘记”；普通点击、停留、滚动、浏览、窗口焦点、调试聊天和未采纳模型输出不参与个人记忆。
2. 候选先按来源、范围、置信度和价值等级保存。
3. 重复证据使候选逐步成为高权重记忆；冲突内容形成新 revision，不覆盖明确内容。
4. 长期未使用或被新内容替代的记忆进入休眠。
5. 其他 Agent 只读取与当前任务相关的记忆，不注入完整个人记忆表。

个人特色主要来自多次明确且稳定的信号，而不是一次偶然问答或被动行为。例如：

- 用户多次要求“先给结论，再给细节”，形成表达结构偏好；
- 用户多次把 Agent 结果改得更简洁，形成长度和风格偏好；
- 多次会话反复出现同一项目术语，形成项目范围术语记忆；
- 用户明确说“以后都按这个方式”，形成高置信度偏好。

用户仍应拥有查看、修改、删除、关闭和“忘记这件事”的控制，但这些控制不应成为正常提取链路的阻塞步骤。该模式参考 ChatGPT 公开的自动更新记忆和可管理控制，但不代表其内部实现。[OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)

`loopback` 中的个人偏好推断作为可选能力提供。默认情况下，没有说话人身份的 `loopback` 内容只形成会话或项目范围记忆；用户可以在后续的个人上下文设置或会话范围控制中选择开启更积极的全局个人偏好提取。该选项不能改变字幕事实，也不能把第三方内容自动改写成权威用户画像。

## 5. 四类主要 Agent 能力

### 5.1 个人记忆 Agent

后台运行，负责从固定字幕快照和允许的交互信号中提取、合并和休眠个人记忆。它不生成整篇聊天式回答，也不修改权威原始转写。

### 5.2 回顾与分析 Agent

用户通过 Agent Bar 提问：

- “告诉我 8 月 20 日到 8 月 25 日发生了什么。”
- “总结这次会议的决定、风险和未完成事项。”
- “分析我最近一直卡在哪些问题上。”

它应先确定时间范围或选区，再读取相关会话经历和字幕来源，最终生成带来源范围的分析报告。

### 5.3 规划 Agent

用户通过自然语言给出目标和约束：

- “根据我的习惯规划下周的工作安排。”
- “按我偏好的节奏安排一个两天行程。”

它读取相关个人记忆、历史经历、时间约束和用户当前输入，生成计划、备选方案、假设和待确认事项。首版只生成内容，不直接写入日历、待办、订票或执行外部操作。

### 5.4 当前上下文 Agent

保留 Typeless 风格的快速能力：对当前选中的字幕或会话进行问答、解释、改写、翻译、提取和增强。它可以产生记忆信号，但普通问答结果不应直接全部进入长期记忆。

## 6. UI 方向

正式用户入口仍建议是紧凑的 Agent Bar，而不是“会话列表 + 聊天首页”：

```text
Agent Bar
├─ 当前上下文：选区 / 会话 / 日期范围 / 项目
├─ 输入：文字，后续可增加语音意图
├─ 意图：由 Agent 自动判断
└─ 结果：回答 / 报告 / 规划 / 派生文本
```

建议的结果形态：

- 问答、解释：轻量浮层或侧栏结果；
- 分析报告：用户主动请求后默认保存为独立、可回看的报告产物；
- 规划建议：带约束和假设的计划草案；
- 记忆更新：后台完成，前台只显示简短状态；
- 交互历史：只保留时间戳、范围/模型身份、最终结果和完整工具调用记录；tool args/result 默认折叠供排障或测试，不保留完整提示或内部思维过程；终态详情允许用户明确导出当前单条交互；
- 报告历史：只按时间戳显示提取后的关键信息，不维护未读状态、角标或计数；
- 原始转写、精修稿、增强文本和报告彼此独立，不能互相覆盖。

低频管理区再提供个人记忆、报告历史、任务状态和设置。旧隔离 Agent 内核开发入口只保留历史资格；重设计可以删除或改造它，它不作为个人记忆来源、正式用户首页或新实现门禁。

## 7. 建议增加的深模块

在字幕提交边界之后，增加一个对外接口较小、内部负责复杂策略的“个人上下文模块”：

```text
ingest(source)
  → 摄取终态字幕或正式 Agent 交互，原子更新会话经历与个人记忆

resolve(request)
  → 相关个人记忆、会话经历、字幕来源、时间范围和预算

manage(command)
  → 查看、修改、删除、休眠、“记住”和“忘记”
```

模块内部负责：

- 选区、会话、日期范围和项目范围解析；
- 个人记忆与会话经历的检索；
- 去重、冲突、revision、置信度和休眠；
- 来源引用和输入水位绑定；
- 每个 Agent 的上下文预算与最小必要注入。

`memory-extraction`、`memory-consolidation`、分析报告和规划建议都通过这个接口工作，不应各自直接读取 SQLite。这样可以让一个记忆规则同时服务多个 Agent，保持修改的局部性。

第二个深模块是“Agent 模型接入层”。可直接借鉴 Pi `@earendil-works/pi-ai` 的实例级模型目录、精确模型选择、OpenAI-compatible provider factory 和 `createProvider()` 形状，但不搬入 coding-agent 的文件、OAuth 或交互式设置产品层。首版只实现 OpenAI-compatible 生产 adapter，DeepSeek 是可修改的预置配置档案，不加入 Gemini 或 Anthropic 原生 adapter：

```text
catalog()
  → provider/model 公开目录、能力和凭据布尔状态

configure(command)
  → 管理多个非敏感配置档案、独立凭据及四个用户模型用途

bind(runRequest)
  → 冻结配置 revision、provider/model、能力、预算和调用级凭据规则
```

Pi 负责 OpenAI-compatible 协议适配与请求派发；本产品继续拥有配置持久化、`safeStorage`、模型用途到内部 recipe 的固定映射、运行冻结、用量记录、失败策略和审计。设置 UI 只显示“默认、信息提取、摘要与总结、分析与规划”，不显示 recipe ID、provider factory 或 adapter。自动重试保持同一模型运行绑定；用户主动换模型测试性价比时创建新 `runId`，避免静默 fallback 破坏可复现性。

交互导出不再引入新的浅模块或第二份数据库事实。renderer 只调用一个窄接口：

```text
exportInteraction(interactionId)
  → storage worker 读取同一终态交互快照
  → main 校验 digest 并编码 canonical JSON
  → main-owned 保存对话框选择目标并原子写入
```

导出包含最终结果、模型运行/用量信息和完整 tool args/result；不包含提示、reasoning、provider 原始事件、凭据、音频或本地路径。相同交互内容重复导出的字节保持一致，便于离线排障和模型比较。

## 8. 与当前设计的具体差异

当前设计保留：

- 字幕系统与 Agent 系统独立；
- Agent 只消费越过字幕提交边界的文字；
- 权威原始转写不可变；
- 个人记忆本地保存、结构化、带来源；
- Agent 能力由 Agent 执行宿主和固定 recipe 管理；
- Agent 故障不能影响字幕系统；
- 首版只生成内容，不执行外部操作；
- 不保存现场音频及其路径。

需要重新定义：

1. 个人记忆的输入不再只限于终态字幕，正式 Agent 交互中的提示、明确编辑、接受、拒绝、“记住”和“忘记”也纳入记忆提取；被动行为、未采纳模型输出和隔离 Agent 内核开发入口明确排除。
2. 增加会话经历记录的正式读取与生成能力。
3. 增加日期范围、多会话和项目范围的上下文解析。
4. 增加分析报告和规划建议两类用户主动触发的固定 recipe。
5. 用只暴露 `ingest(source)`、`resolve(request)`、`manage(command)` 的个人上下文模块替换 `MemoryReader`；所有 recipe 都通过该深模块取得有界个人上下文包。
6. 把当前“确认后才进入长期记忆”的语义改成“自动形成、按置信度和范围逐步生效”，但保留用户事后管理。
7. 将 `loopback` 的全局个人偏好提取设计为可选策略：默认只形成会话或项目范围记忆，开启后才允许更积极地形成全局偏好；仍需保留来源和范围。
8. 用可扩展的 Agent 模型接入层替换单一 DeepSeek catalog 与 `DEEPSEEK_API_KEY` 产品入口；首版只支持 OpenAI-compatible 调用格式，DeepSeek 作为预置配置档案。
9. 正式交互历史不保存完整提示或模型 reasoning；保存最终结果及工具接口预算内完整的 tool args/result，正文默认折叠并与日志、报告和个人记忆隔离。
10. 正式交互详情提供用户明确触发的单交互 JSON 导出；导出直接读取 SQLite 当前事实，不建立导出表、导出历史或自动批量任务。

## 9. 建议的首版范围

首版先闭合以下能力：

1. 终态会话自动提取会话经历和结构化个人记忆。
2. 正式 Agent 交互产生可控的记忆信号。
3. 在字幕历史中选择一段记录或日期范围，生成带来源的回顾/分析报告。
4. 用户主动请求的分析报告默认自动保存；即时问答不自动保存为报告。
5. 根据个人记忆和用户输入生成不执行外部写入的规划建议。
6. 其他固定 Agent recipe 通过统一上下文接口读取相关个人记忆。
7. 首版正式入口先采用文字 Agent Bar，语音意图在单独完成命令输入契约后再接入。
8. 设置中可保存多个 OpenAI-compatible Agent 模型配置档案，提供 DeepSeek 预置档案，只暴露默认、信息提取、摘要与总结、分析与规划四个模型用途，并支持用户主动换模型重跑比较。
9. 终态正式 Agent 交互支持导出 canonical、带 schema 版本的 JSON，包含最终结果、模型运行信息与完整工具调用记录。

首版暂不引入：

- 向量数据库、图数据库或不可重建的语义索引；
- 自动写日历、待办、邮件或外部系统；
- 把完整聊天正文、完整字幕正文复制成第二份**可检索个人知识库**；这条禁止的是第二个知识来源，不禁止工具调用记录中受 Schema 与预算约束、随交互级联删除、不进入日志/报告/个人记忆的有界审计证据；
- 把隔离 Agent 内核开发入口产生的内容写入正式个人记忆；
- 让个人记忆控制字幕识别或静默修改权威原始转写。

## 10. 本轮对齐决定

1. **记忆来源**：正式 Agent 交互中的提示、明确编辑、接受、拒绝、“记住”和“忘记”可以成为记忆信号；被动使用行为、未采纳模型输出和隔离 Agent 内核开发入口不进入个人记忆。
2. **结果沉淀**：正式交互历史只保留时间戳、范围/模型身份、最终结果和完整工具调用记录；完整提示在信号提取后清理，内部思维过程和 reasoning 不持久化。工具接口预算内的完整结构化参数/返回结果保存在本地交互审计中，默认折叠，随交互级联删除，且不进入日志、报告、个人记忆或测试证据 JSON。只有稳定的事实、结论、偏好和个人风格进入个人记忆。
3. **`loopback` 个人偏好**：作为可选能力提供。默认只形成会话或项目范围记忆；用户开启相关选项后，才允许更积极地形成全局个人偏好。
4. **报告保存**：用户主动请求的回顾、趋势分析和项目总结默认自动保存为独立报告；即时问答不默认保存为报告。报告历史不维护未读状态、角标或计数，只保留时间戳和提取后的关键信息。
5. **规划范围**：首版只依据本地字幕、个人记忆和用户输入生成规划建议，不直接读取外部信息，也不修改日历、待办或执行预订。
6. **交互入口**：首版先采用文字 Agent Bar；语音意图等待独立的命令输入契约完成后再接入。
7. **默认报告行为**：终态会话默认只触发个人上下文摄取，不生成也不呈现报告。用户可以主动打开或请求报告；另提供默认关闭的报告自动呈现偏好，开启后只影响未来终态会话，并在 Agent Bar 非模态呈现一次会后结构化纪要。无论偏好状态如何，都不产生未读标记。
8. **执行宿主**：首版不建设插件生态。普通提取、改写和单次问答走结构化模型请求；只有需要受控只读工具的跨会话分析或规划才运行有 turn/token/时间/工具预算的 Pi Agent Loop。
9. **多模型接入**：首版只保留 OpenAI-compatible 生产 adapter，DeepSeek 是可修改的预置配置档案，不加入 Gemini 或 Anthropic 原生 adapter。接入层采用 Pi 的实例级模型目录、精确模型选择与 OpenAI-compatible factory，产品自身管理多个配置档案、每档案独立 `safeStorage` 凭据及四个模型用途。
10. **模型比较**：同一来源可以由用户主动换模型建立新 `runId` 重跑，按 provider/model、token、相对时长、结果版本和可选费用估算比较提取与总结的性价比；自动重试不得静默换模。
11. **设置抽象**：普通用户只看到默认、信息提取、摘要与总结、分析与规划，不看到内部 recipe、adapter、factory 或协议注册表；高级连接信息只留在具体模型配置档案内。
12. **交互导出**：每个终态交互保留一个明确“导出”动作，旁边简短提示文件包含完整工具输入与结果；导出为确定性单交互 JSON，不自动、不批量、不支持导入，也不进入报告或测试证据目录。
