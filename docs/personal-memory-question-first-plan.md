# 提问优先的个人记忆实施规划

用户需求方向：**已决定**。本文件细化本轮用户提出的来源顺序：先从用户提问形成个人信息和偏好，再用这些信息关联会话，保留与用户有关的经历。它是实施规划，不表示新增能力已有实现或验收证据。

推荐方案见 [个人记忆与会话总结体验](research/personal-memory-experience-proposal-2026-09-30.md)。规范以 [CONTEXT](../CONTEXT.md)、[语义合同](semantic-contract.md) 为准；下述差异必须先登记，再实施。

## 1. 来源与确认规则

优先次序是：用户明确记住、确认和纠正 → 正式 Agent 提问中的本人陈述与长期要求 → 多次独立提问形成的候选 → 与已确认用户信息相关的会话背景。

“来自用户提问”描述证据来源；“已确认”描述条目状态。自动模型提取仍先形成记忆候选，不能只因为源文本由用户提交，就把所有提取结果写成 origin='explicit'。来源、确认状态、置信与作用范围分别治理。

| 用户输入 | 首版处理 | 范围 |
|---|---|---|
| “以后解释技术时，先给一个小例子” | 长期表达偏好候选；确认后成为明确内容 | 可提出全局范围，仍遵守候选规则 |
| “我负责示例项目 X 的客户端” | 本人项目职责候选；确认后可用于关联会话 | 项目范围 |
| “这次只列三点” | 本次产物约束 | 本次运行，不形成长期偏好 |
| “缓存是什么” | 当前问题 | 不推断职业、长期兴趣或技能水平 |
| “同事说他喜欢简短回答” | 第三方陈述 | 不形成用户本人偏好 |
| “假如我是项目负责人……” | 假设 | 不形成本人身份或职责 |

一次提问中的明确长期要求可以提出候选；只从提问方式推断的习惯，首版建议至少取得两次不同任务中的独立用户表达。阈值在登记片固定；重复提交、重试、助手复述、引用的第三方原文和既有记忆注入均不计为新证据。多次候选也不会自动变成用户明确内容。

本人信息主要使用用户确认的项目、职责、目标及允许复用的背景。没有这些信息时，个人背景保持空缺，仍可以正常保存和查看一般会话经历记录。

## 2. 两类摄取沿现有执行路径实施

### 用户提问

正式 Agent 入口已受理的用户提示和明确反馈 → 按受信任动作分离用户文字、引用文字与助手结果 → 提取本人陈述、长期要求及候选 → 验证来源/范围/冲突/预算 → SQLite 原子提交 → 用户查看、确认、纠正 → resolve 使用当前有效条目。

第一片只扩展已有正式交互能力，不新增通用聊天首页，也不从当前 Codex 对话、调试聊天或其它应用自动收集问题。当前正式请求的范围与 Agent 处理资格继续成立；用户手动“添加记忆”走 manage，不要求模型在线。

用户提问的归属不依赖助手回答是否正确或被用户接受。回答失败与取消时的提示处理，需要按现有资格和提示清理生命周期登记真实旅程；不能因此永久保存完整问题。结果接受、拒绝和编辑可以辅助判断，助手未被采纳的输出本身不作为用户事实。summary.minutes 普通信号继续排除。

### 会话内容

合格终态会话确定完整提交水位 → 冻结当前授权范围内已确认用户信息及其 revision → 同一 context.ingest.session 运行接收有界用户信息与正文 → 模型提出结构化会话经历和关联 → 个人上下文模块核对等值匹配、双侧来源、范围和当前有效性 → 原子提交一般会话经历记录与合格关联。

会话关联是已有会话经历记录的有来源补充，不建立新的执行系统或独立权威存储。仍使用已登记 recipe、同一 Agent Loop 和 ingest/resolve/manage；不增加自由工具、SQL 或全文检索接口。

SEM-F26 目前只允许 NFKC + casefold 后的结构化字段、规范化语义键与已登记别名等值匹配。模型可以从正文提取结构化项目/角色/实体并提出关联；模块不把“查找个人信息”实现为 SQLite LIKE、子串、分词、模糊或向量检索。模型提出的关联保留为可审阅内容，不冒称确定的身份识别。

每项有效关联必须同时能追溯：

- 用到的已确认个人记忆身份、revision、作用范围，以及相应正式交互或用户管理来源。
- 会话身份、正文版本、提交水位、digest 和相关字幕来源引用。
- 匹配的结构化依据，以及它支持的是项目背景、相关经历还是明确归属的事项。

没有有效个人信息或匹配依据时，只保留一般会话经历记录，不增加一次专门的“猜测本人”模型调用。只有相似话题或同名时保留不确定性，不把会话中的“我”当成本应用用户；mic 和 loopback 适用同一规则。

例如，用户已确认自己负责示例项目 X，会话提到 X 的接口变更，可以形成“用户负责的项目出现接口变更的相关背景”。它不能变成“用户作出了变更决定”，更不能成为“用户偏好这种接口设计”。当前来源尚未确认时，可以展示“可能相关”的提示，但不建立明确长期关联，也不用于增强原候选置信。

## 3. 分片与依赖

| 顺序 | 目标与主要工作 | 交付出口 |
|---|---|---|
| 登记片 | 对齐 CONTEXT、SEM-F26/F27/F30/F31/F32/F37/F38、J21/J22/J28/J29 和既有 change；固定本人背景种类映射、来源优先、候选规则、双侧证据、来源时间/摘要/跳转、旧数据处理和关联撤销 | 术语、合同、旅程、proposal/design/spec/tasks 一致；新任务保持未勾选，保留已有总结证据 |
| 第一片 | 提问中的用户文字与引用/助手文字分离；本人陈述、长期要求、本次限制、假设与代问分类；候选确认和纠正 | 正式提问 → 候选 → 查看来源 → 确认/修改 → 后续 Agent 读取 → SQLite 重开一致，覆盖 J21/J22 |
| 第二片 | 会话摄取绑定有界已确认用户信息；等值关联、双侧来源、撤销与旧响应拒绝 | 相关会话 → 关联说明 → 修改/删除本人信息 → 旧关联不可读，覆盖 J21/J28 |
| 第三片 | 我的记忆默认个人视角、直接编辑；来源显示时间与短内容，并跳转精确记录；会话总结显示实际纳入输入的记忆与关联依据 | 正式 settings/agent/history renderer、preload、main、Loop、SQLite 的 J28/J29；精确定位、提示已清理/记录删除/导航失败；参考关闭与休眠排除个人信息，J30/J31 既有约束保持 |
| 第四片 | 选择、预览、复制、Markdown/JSON；个人明确内容与相关会话背景分别选择 | J28 导出子旅程：同一快照、范围、确认状态、撤销竞态、取消/写失败；导出零模型调用 |
| 后续片 | 后台 context.synthesize 综合；独立交付只读 MCP | 综合的输入身份/覆盖/失效和 MCP 的范围/预算/休眠/撤销各有真实旅程 |

关键依赖：会话长期关联先依赖可管理、可撤销的已确认用户信息；个人概览和对外内容依赖这些关联的有效性。现有总结运行反馈、取消与长输入验收可以继续进行，不需要等待关联功能，但不能当作新记忆策略的证据。

第一片的主要落点：

- [recipe 与输出合同](../src/agent/contracts/recipes.js)：当前 ContextIngestV1 的会话 evidence 和交互 evidence 各自只有单侧引用。双侧关联及本人信息输入必须新增经登记的版本化合同/静态 recipe 版本；不在旧 exactObject 中暗加字段，也不改旧运行绑定。
- [摄取 runner](../src/agent/execution-host/context-ingest-session-runner.js)：复用正式交互/会话分支，准备冻结输入并调用同一 Loop；当前有界输入不能静默截断。新增用户信息也计入总预算，不另设无界输入。
- [个人上下文接口](../src/agent/personal-context/index.js) 与 [存储模块](../src/runtime/storage-worker/personal-context-store.js)：来源优先、确认、作用范围、双侧依赖、revision 校验、原子提交与失效；经 manage 返回有界的来源时间、可读依据、可访问状态和经校验的导航目标，外部调用者保持三接口。
- [记忆管理界面](../src/settings/agent-context-pane.tsx)：复用已有 manage，展示可读来源、确认状态和查看记录动作； [总结界面](../src/agent/agent-view.tsx) 保留四栏合同并展开实际记忆输入与关联依据。main/preload 将受控导航目标交给正式交互详情或字幕历史，不让 renderer 拼接事件标签、数据库条件或任意 URL。

新增字段与投影经 forward-only migration；实施前读取 data-architecture 的相关章节与 ADR 0001。IPC 白名单、preload、UI 合同和 renderer 随同更新，不引入第二套数据库或 JSONL 权威副本。背景种类映射先登记，不能为了快速交付把所有本人信息塞进 project_fact 或悄悄增加枚举。

## 4. 用户可见体验

“我的记忆”优先展示偏好、本人背景与目标、当前项目和约束。正文直接修改；来源默认展示“来源发生时间 + 简短内容 + 查看记录”，确认状态另行显示。用户能点击时间或短内容打开对应记录，不需要理解事件标签、交互 ID、recipe、revision、digest 或来源引用数量。

### 来源展示与跳转

以下内容仅为界面示例：

| 来源 | 默认看到的内容 | 点击后的目标 |
|---|---|---|
| 用户提问 | 9月30日 09:32 · 提问摘要：希望技术解释先给一个例子 | 对应正式交互记录，显示结构化提问摘要和已保留结果；不默认展开工具审计 |
| 会话正文 | 9月30日 15:10 · 项目 X 讨论 · 12:18–12:46；原文摘录：“客户端接口需要调整……” | 对应字幕历史、明确正文版本和引用段范围，定位并突出显示相关文字 |
| 用户添加/修改 | 10月1日 09:20 · 手动修改：回答先给结论 | 对应个人记忆条目；修改历史若未对用户开放，不冒充能打开旧版正文 |

时间是来源发生时间，记忆“更新时间”另行展示。会话行的日期时间表示会话开始时间，后面的相对位置表示具体引用范围，不伪装成精确发生的墙钟时间。时间按用户当前时区格式化，跨年显示年份；旧记录缺少时间时明确显示“来源时间未知”，不以记忆更新时间补造。

短内容默认控制在两行内。会话摘录从对应权威正文版本按引用范围读取；提问摘要来自摄取时保留的有界结构化关键信息，清楚标为“提问摘要”，不加原话引号，也不在每次打开时让模型重新编写。显示截短仅影响预览，不改变来源范围、内容覆盖或机器引用。摘要的预算和提问清理边界先登记到 SEM-F31/F32，不能复制完整原问题、结果或工具正文作为来源摘要。

原始提示按生命周期清理后，仍可打开存在的正式交互记录，明确显示“原问题正文未保留”，并展示保留的摘要/结果；不存在摘要的旧记录显示“未保留提问摘要”。对应记录已删除或来源已撤销时，不展示旧摘录，提供“记录已删除”或“来源已失效”状态，跳转不可执行。暂时无法读取时提供重试，不能导航到时间接近但身份不同的记录。

点击会话来源必须按内部稳定身份、正文版本和段范围精确定位；目标不在当前分页时继续有界读取对应页，不跳到列表顶部或按标题猜测。打开记录沿正式 main/preload/IPC 边界执行，再核对来源与作用范围；点击和查看本身不创建运行、不调用模型、不形成交互记忆信号。退出记录后返回原记忆位置。

一条记忆有多个来源时，展示独立的时间与短内容，可展开其余来源；不能只显示“引用 3”或一个类型标签。会话关联分别展示支持用户信息的那条记录和相关会话片段，并用一句自然语言说明关系，例如“你提到负责项目 X，这段讨论涉及 X 的客户端接口”。两侧都可查看，任一侧失效即按关联规则处理。

内部身份、revision、水位和 digest 继续保留用于核验、去重、撤销与 Agent 读取；普通来源界面不暴露这些字段。外部 Markdown 中使用可读的时间与短摘要，JSON 保留经登记的结构；本应用内部跳转不冒称外部 Agent 可访问，也不导出本机绝对路径。

普通会话经历记录保留在“会话要点”，不因为被采集就进入个人背景。用户可以确认、修改或拒绝候选；对自动判断的反例反馈只在明确动作后成为交互记忆信号，浏览行为不作为反馈。

会话总结继续按主要内容、决定、待办、需要注意展示，不把未确认事项改写成个人承诺。参考记忆开启且有有效关联时，增加来源详情“与你的关联”；关闭参考或个人记忆休眠时，本次总结不读取这些个人信息。它不改变后台摄取资格，也不允许把后台关联结果塞回关闭参考的总结输入。

外部导出默认选用户已确认的个人内容；项目事实与相关会话背景另行勾选。关联背景带确认状态和双侧来源，不携带整场字幕或工具审计。项目内 Agent 经 resolve 取得有界内容；MCP 后续仍是按范围授权的只读入口。

## 5. 修正、撤销与旧数据

用户明确内容始终优先于自动推断。当前问题的临时要求作用于本次结果；与长期明确值冲突的自动提取只形成冲突候选，不能后台覆盖。

修改、忘记或删除用于关联的个人信息，先撤销以旧 revision 建立的关联，再重建可派生视图；只由该关联支持的本人结论不可继续注入或导出。若其它有效来源仍足以支持某项普通会话事实，模块重新校验后可以保留它。迟到模型响应、失败重试和旧概览都不能恢复被撤销依据。

现有 SEM-F26 允许旧积极策略产生 loopback 全局偏好候选，本轮方向需要替换它：会话自动提取先留在会话/项目范围，经用户明确确认归属与选择范围后才形成全局明确内容。旧开关如何兼容或迁移、旧自动条目如何标记为待复核，必须先登记；不批量删除用户已确认条目。

旧自动条目若只由未关联会话支持，不能继续充当全局本人信息或偏好。保留可审阅的处理记录与既有来源/suppression，明确条目继续尊重用户确认。不存在完整历史提示时不伪造提问来源；新策略不自动重建已清理提示，也不补跑旧字幕历史。

旧会话重新整理仍由用户明确选择范围并提交，个人记忆重新开启建立新自动处理边界，不追补关闭期间来源。已经复制给外部 Agent 的副本由接收方处理，撤销只约束本应用后续读取与新导出。

## 6. 必须登记的旅程与失败路径

第一条纵向旅程：用户通过正式 Agent 提问说明本人项目与长期表达要求 → 候选查看 → 用户确认 → 相关合格终态会话 → 双侧依据查看 → 修改本人信息 → 旧关联失效 → resolve 使用当前有效信息 → 选定内容导出 → SQLite 重开一致。

| 子边界 | 必须验证的反例 | 既有旅程 |
|---|---|---|
| 提问归属 | 一次知识问题不推断职业；引用/假设/代问不归本人；临时要求不升级长期偏好；未采纳助手输出不形成本人事实 | J21/J22 |
| 独立证据 | 同一问题重试或重复唤醒不增加候选数、独立证据数或置信；接受并不自动确认所有提取结果 | J21 |
| 会话关联 | 无个人信息、无关内容、同名与角色不一致、只有话题相似时不形成明确本人关联；项目关联不变成用户决定或待办 | J21/J28 |
| 双侧来源 | 模型提供未冻结用户条目、越界会话引用、过期 revision 或已删除来源时拒绝提交关联；整次操作原子收束 | J21/J28 + DB7 |
| 来源展示与导航 | 时间来自原记录而非记忆更新时间；跨年/时区正确；摘要与原文摘录区分；不在当前页的目标仍精确定位；提示清理后只显示真实保留内容；已删/撤销来源不泄漏旧预览，导航失败保留当前位置并可重试；查看不触发模型或摄取 | J28/J29 + J12 |
| 撤销 | 信息修改/忘记/删除后旧关联、当前及上版概览、新读取和新导出排除无效内容；后台失败/旧响应不能恢复 | J28/J12 |
| 总结隔离 | 参考关闭或休眠时输入不含个人信息与跨会话关联；普通总结信号零写入；单独记住动作有真实管理提交 | J29，保留 J30/J31 |
| 独立性与隐私 | provider 失败、取消、超预算或关联失败不阻断字幕保存与下一会话；原始提示及时清理；证据 JSON 只含指标、布尔与哈希 | J12/J21/J29 |

内部产品模块使用真实实现；替身只位于模型、网络、系统权限或外部 Agent 等不可确定边界。确定性旅程证明范围、归属合同、来源及生命周期；提问分类和会话关联的实际模型质量另外使用合成语料核对，不把 provider 替身当作模型准确率证据。
