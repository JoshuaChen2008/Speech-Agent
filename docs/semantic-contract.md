## 2. 规范语义表

下表中的“必须”是验收要求。“当前状态”只陈述截至 2026-08-09 的证据，不能用来降低要求。

> **SEM-F24 本轮恢复等价说明（2026-08-10）**：字幕窗外框的 `x/y/width/height` 恢复继续逐项 exact；工具条以 `getContentBounds()` 的可见视口 `x/y/width/height` 逐项 exact，Win32 对透明无框外框额外归一的 `1 DIP` 不得被保存为内容视口或下一次停靠基线；设置与字幕历史的 Win32 外框在非整数系统缩放下允许每项最多 `1 DIP` 的物理像素归一等价，只有四项全部落在该界内才可视为稳定且不得继续重置安静期。该容差不得用于字幕窗、工具条、停靠公式、拉伸或拖动，也不得吞掉测试主动注入的明显漂移；辅助窗口下一次最小化从已经归一的实际 bounds 取样，重复恢复必须幂等，不能每轮累计 `1 DIP`。`1000ms` 普通结算上限到达时允许发起最后一次纠正；若该次纠正确实调用了 `setBounds`，窗口交互代次必须继续保持 `suspend`，再进入固定且不因后续 `move`/`resize` 延长的最多 `250ms` 原生提交确认期。确认期终点不得再次写 bounds，只能复读全部窗口；caption/toolbar 仍非 exact 或辅助窗仍超出等价界时必须进入既有 `post-restore-bounds-failed` 降级并保持 `suspend`，不得强制 `resume`。

> **SEM-F24 最终确认期说明（2026-08-10）**：上述固定原生提交确认期从最终纠正写入后开始即为只观察阶段，不只是终点只读。期间到达的 `move` / `resize` 只能保留为最终复读事实，不得再触发 `setBounds` / `setContentBounds`；该禁写约束同时覆盖恢复控制器与工具条固定停靠纠正器等所有窗口几何写入者，否则确认期末的同步读回仍可能早于最后一次异步 Win32 提交。确认终点仍不等价时只走既有 `post-restore-bounds-failed` 降级，零 `resume`。任一窗口的失败观测都不得成为下一次恢复基线：下一次 `restoreOrShow` 必须复用本次失败前保存的窗口集合、字幕窗/仍存在辅助窗的 bounds 与工具条最近一次合法预期，重新完成有界几何结算后才可提交显式工具条预期并恢复交互；该待重试状态只有成功 `resume` 后才能清除。用户在结算中或降级后明确关闭的设置/字幕历史必须从恢复集合移除，不得因已销毁辅助窗再次降级；字幕窗和工具条缺失仍保持 fail-closed。

> **SEM-F22 本轮增量说明（2026-08-10）**：接受有效工具条轮廓后，主进程必须在同一窗口交互代次按当前系统指针同时重命中字幕窗与工具条；工具条 renderer 的 `ResizeObserver` 还必须先按已知本地指针同步重命中，再延后上报轮廓，不能让轮廓扩张把静止指针留在两窗都穿透的死区。首帧、reload 或报告失效时的最坏尺寸穿透区由当前 `20 DIP` 停靠内缩与 window-local `16..584 DIP` 最大真实轮廓推导为 `588 × 64 DIP`，必须完整包含最大真实轮廓。工具条原生内容视口始终为 `600 × 72 DIP`，BrowserWindow 创建时必须声明 `useContentSize: true` 使首个可见提交前的 `width/height` 就表示内容视口；停靠、恢复以及系统指针到 renderer 局部坐标的换算都以 `getContentBounds()/setContentBounds()` 为准；外框宽高若因 Win32 缩放归一多出 `1 DIP`，只有内容视口仍逐项 exact 时才不是工具条扩张，且该外框差值不得进入权威几何；frameless/transparent BrowserWindow 不得用 exact `minWidth/maxWidth/minHeight/maxHeight` 代替该不变量，因为 Win11 对程序化平移重新归一外框时可能把这组约束反向放大为新尺寸。所有会移动工具条的手动拖动帧必须显式提交固定宽高，`resizable: false` 只关闭用户原生拉伸入口；Windows 恢复或 DWM 重新组合引发的非用户 `resize` 必须立即归一到固定尺寸，不能累计成外扩：未锁定时按字幕窗当前 bounds 重新停靠，已锁定时使用最近一次合法握把/组合几何结算提交的权威 `x/y`，不得把 resize 后的漂移坐标当成新基线，也不得把用户单独移动后的工具条吸回字幕窗。一次 `setContentBounds` 后同步读到目标值不能单独证明 Win32 已结算；纠正器必须保留可取消的 `250ms` 再确认，并在旧原生提交晚到且没有后续指针移动时再次恢复当前权威几何。合法握把/组合结算或锁定状态切换必须取消旧目标并替换为新权威值，不能让旧确认把新位置拉回。单个目标最多发出四次纠正写入（最长 `1000ms` 确认窗口）；同一目标与同一 content/outer 观测几何的尾随原生双事件不得消耗额外写入额度，只有有界再确认到期或观测几何确实改变才可发出下一次写入。仍不收敛时记录既有固定视口纠正失败，并同时锁存当前目标与当时观测到的 content/outer geometry。同一轮纠正尾随的原生 `move/resize` 若目标和观测几何都未变化，不得清除锁存或开启新一轮写入；显式合法几何提交、锁定状态切换、恢复事务、当前停靠目标真正改变，或故障后原生事件确实带来不同的观测几何，才可开启一轮新的有界重试，不能形成永久写入风暴，也不能永久屏蔽后续真实系统变化。每次成功纠正实际改变工具条 bounds 后，主进程必须在同一窗口交互代次按当前系统指针重命中工具条；没有实际纠正时不得伪造几何结算。最小化事务只能保存按当前锁定状态重新求得的预期位置与归一后的固定宽高；切换锁定必须先结束旧锁定状态下仍活动的组合/握把手势，再取得旧状态的合法预期位置，之后才可翻转锁定状态并显式提交，不能让 `stopAll()` 的结算回调在新锁定状态下把恰逢其时的 DWM 晚到坐标写成下一次恢复或锁定基线。固定视口纠正失败只记录 exact `{ role: 'toolbar', code: 'toolbar-dock-correction-failed' }`，保持主任务栏入口可达并在下一次带来不同观测几何的原生 `resize` 或恢复事务重试；该几何降级不扩入 SEM-T04 的窗口交互代次同步四码闭集。字幕窗与工具条属于同一原生输入序列：主键结束若由非发起 overlay 接收，主进程在停止活动 timer 后必须推进一次窗口交互代次并同步 `suspend → resume`，同时清理发起 renderer 的活动 pointer、待定拉伸与 CSS 状态；若该代次重置不能成立，字幕窗必须保持穿透、工具条保持实心，等待 reload 或下一次恢复事务，不能新增未登记的交互同步 code。renderer 收到同一鼠标主指针 ID 的下一次合法主键按下时，也必须先原子收敛本窗可能遗留的旧手势，再处理当前输入，不能因旧 pointer ID 拒绝下一次拖动或按钮点击。真实主键输入调用 `setPointerCapture` 后，若浏览器提供 `hasPointerCapture` 且立即返回 `false`，必须与抛错相同地收敛本地状态和主进程 timer；受控产品壳注入的非可信 DOM 事件不冒充原生捕获。J17 必须对称覆盖 caption→toolbar 与 toolbar→caption 的跨窗结束、尚未达到 `4 DIP` 的待定拉伸跨窗结束、随后第一次新拖动、无抛错但捕获未建立、固定视口创建约束、同步读回后再被旧原生提交覆盖的有界再纠正、固定视口成功纠正后的工具条重命中，以及轮廓扩张后静止指针的双 renderer 重命中；J19 继续覆盖恢复结算与固定工具条视口。

> **SEM-F22 轮廓观察补充（2026-08-10）**：上文的 `ResizeObserver` 不能被实现为唯一的 DOM 轮廓失效入口。隐藏、遮挡或后台调度中的 Chromium 可能延后该回调；工具条自身的子节点、文字、class 或 style 变化还必须由 `MutationObserver` 微任务入口触发同一同步重命中，再延后上报轮廓。两种观察任一先到都必须幂等，且不能等待下一次 `mousemove` 或 rAF 才让新轮廓实心。renderer 收到 `mouseleave` 后必须使此前的局部指针坐标失效；后续轮廓观察不得用该旧坐标把已经离开的工具条 HWND 重新变实心，直到新的本地移动或权威同代指针重命中到达。

> **SEM-F22 工具条握把可见性修正（2026-08-10）**：工具条嵌入字幕卡且字幕未锁定时，拖动握把必须从布局、实际轮廓和指针命中中移除；此时只能从字幕卡普通拖动区移动字幕窗与工具条组合，toolbar renderer 与主进程都必须拒绝未锁定的工具条拖动意图。字幕锁定、工具条脱离字幕卡后，两列三行六点握把才进入既有 `24 × 30 DIP` 命中盒，并作为工具条唯一拖动入口。锁定状态切换必须先收敛旧握把手势，再使工具条轮廓失效、按静止指针同步重命中并上报新轮廓；不得让被隐藏的旧握把命中盒或迟到意图触发字幕窗拉伸、组合拖动或 bounds 漂移。该修正为实现完成·尚未验收：确定性 UI/主进程/联合旅程与 schema-v8 产品壳协议已覆盖，I2 `dwm-drag` schema-v6 实机报告尚未取得。

> **SEM-F22 解锁字幕卡逐像素命中修正（2026-08-10）**：Windows 上不可聚焦的字幕 BrowserWindow 已进入原生鼠标穿透后，Electron 的 `forward: true` 不得作为指针重新进入可见字幕卡的唯一观测来源；否则 renderer 未收到移动事件时，解锁字幕卡会一直保持穿透，主键按下无法产生字幕拖动意图。应用处于当前窗口交互代次的 `resume`、字幕窗可见且没有活动拖动/拉伸时，主进程必须以有界、帧级轮询读取当前系统指针，并用与 renderer 相同的 `20 DIP` 透明外边距、工具条当前有效 overlap rect 和可见字幕卡几何预先同步字幕窗原生鼠标穿透。该补充不得把整个透明字幕 BrowserWindow 设为实心，也不得改变 `focusable: false`：透明外边距、工具条实际轮廓与锁定字幕窗继续穿透；活动手势、`suspend`、renderer reload、过期代次和既有 SEM-T04 降级优先，轮询不得绕过窗口交互代次或把失败状态恢复成实心。主进程只在计算命中状态改变时写原生穿透，窗口 bounds、工具条 overlap 或锁定状态改变后必须重新判定；指针坐标仍只存在于有界内存，不得进入日志、数据库、导出或证据报告。原生 setter 失败继续使用既有 `interaction-pass-through-failed`，不新增诊断码。该修正为实现完成·尚未验收：主进程命中矩阵、轮询缓存/失败边界、窗口交互代次约束、J17 跨模块拖动旅程与 I2 真实 HWND 入口接线已覆盖；真实 Windows 主键连续性、DWM、DPI 与异缩放仍由 I2 `dwm-drag` schema-v6 验收。

> **SEM-F22 全窗纯位移修正（2026-08-10）**：主进程手动拖动字幕窗、工具条、设置窗或字幕历史时，每一帧都只能改变该窗口的 `x/y`，并必须在同一次原生几何提交中携带手势开始时冻结的 `width/height`；不得把 Electron `setPosition()` 或其它 position-only 原生调用当作唯一写入，因为 Win32 normal placement、无边框窗口组合或 DPI 归一可能把陈旧尺寸反向提交为新 bounds。工具条继续按固定 `600 × 72 DIP` 内容视口提交；字幕窗、设置窗与字幕历史按各自手势起点的完整外框 bounds 提交，字幕窗只有独立的显式拉伸手势可以改变宽高。确定性层必须对四个窗口角色注入“position-only 写入会夹带尺寸漂移”的原生边界，并证明连续拖动、原地松开与组合停靠都不改变冻结宽高；I2 `dwm-drag` 继续观察真实 DWM、DPI 与异缩放。该修正为实现完成·尚未验收：共享主进程拖动器与 J17 四角色联合旅程已覆盖冻结宽高、组合停靠和 position-only 尺寸回写边界；当前候选尚无 I2 `dwm-drag` schema-v6 实机报告。

> **SEM-F22 混合缩放工具条几何收敛（2026-08-20）**：工具条固定 `600 × 72 DIP` 内容视口的全部原生几何写入必须由同一个停靠协调器提交；普通停靠、锁定态工具条拖动、字幕窗组合拖动、启动对齐与任务栏恢复不得再直接调用工具条 `setBounds` / `setContentBounds` 形成竞争写入。任务栏恢复进入受管结算时必须暂停协调器的自主纠正，按既有 `250ms` 安静期、`1000ms` 最终纠正边界与写入后最多 `250ms` 固定确认期收敛；只有逐项 exact 的工具条内容视口和停靠关系得到确认后才能采用新基线并恢复自主纠正，失败时保持 `suspend` 与显式降级。旧配置未带 `windowGeometryRevision=1` 且字幕窗尺寸精确为 `1373 × 168 DIP` 时，启动加载必须一次性归一为既有默认 `920 × 190 DIP` 并原子持久化修订标记；其它旧尺寸原样保留，带标记后的 `1373 × 168 DIP` 也视为用户明确配置并原样保留。该内部标记不得进入 renderer 配置快照或放宽 ConfigStore 白名单。该增量为实现完成·尚未验收：ConfigStore、J17/J19 确定性旅程和三种 schema-v8 产品壳配置已覆盖；真实鼠标、DWM 与异缩放双屏仍沿 I2 `dwm-drag`。

> **SEM-F24 双窗口有界启动恢复（2026-08-20）**：字幕窗与工具条的启动就绪以各自 renderer 载入成功和工具条 exact 停靠结算为准，不得把两个 `ready-to-show` 事件作为唯一显示闸门。每次启动尝试最长 `5s`；等待期间字幕窗保持隐藏，工具条必须以不透明、可交互且可从任务栏找到的主入口显示。两项 renderer 与 exact 几何均就绪后，才切回工具条透明表面、显示字幕窗并启用当前窗口交互代次。任一载入失败、超时或几何结算失败时，工具条继续提供“重试 / 退出”；重试必须使旧尝试 token、timer 和迟到回调失效，并重新执行完整载入与结算，退出进入 SEM-F12 正常退出序列。固定诊断与确定性报告不得包含路径、窗口几何、设备名或绝对时刻。该增量为实现完成·尚未验收：有界启动控制器失败矩阵、main 接线约束和三种 schema-v8 产品壳配置已覆盖；真实任务栏与 DWM 仍沿 I2 `dwm-drag`。

## 3. 变更维护规则

1. 需求、实现或测试 PR 必须引用至少一个 `SEM-*`；没有适用项时先新增语义行。

4. “当前状态”至少在阶段验收、存储后端切换、摘要上线和发布前复核一次。
