## Goals / Non-Goals

**Goals:**
- 用户能查看持续更新的记忆概览及来源，并纠正或移除错误内容。
- 用户一眼理解会话总结入口，点击必有反馈，明确哪场会话、是否参考记忆。
- 自动整理与总结读取分别受控；总结运行不自动写入个人上下文。
- 真实产品旅程验证删除、并发、失败和字幕独立性。

**Non-Goals:**
- 不加入跨项目分析报告、日历/邮件操作、会中滚动总结、自动呈现纪要、音频保存或向量索引。
- 不重新设计模型配置向导；不删除既有问答、历史和 JSON 导出。
- 不承诺全部历史都被自动处理，不从时间经过推断计划已经执行。

## Decisions

### 1. 两份 spec，一个共同边界

任务 A 为“我的记忆”：后台摄取产生会话经历记录/个人记忆，再维护个人记忆综合视图。任务 B 为“会话总结”：只读本次正文，可选择性读取个人记忆，产生独立会后结构化纪要。B 可以先使用既有个人记忆实现，不等待 A 的综合视图；综合视图不作为 B 的额外事实来源，避免重复注入和转述放大。

选择共享 change 是因为二者都涉及 SEM-F30/F32 和设置，不适合两份互相矛盾的开关合同。实施按任务顺序推进，不能一次铺开全部红测。

### 2. 对用户说目的，对内部保留精确定义

| 内部规范术语/动作 | UI 展示 | 必要说明 |
|---|---|---|
| 个人上下文模块的管理表面 | 我的记忆 | 自动整理会话中的重要信息，也可以自己添加。 |
| 个人记忆综合视图 | 记忆概览 | 根据已整理的信息更新，不代表全部历史。 |
| 个人记忆条目列表 | 记住的内容 | 展示明确添加或自动整理的来源区别。 |
| 会话经历记录 | 会话要点 | 来自哪次会话，以及当时发生了什么。 |
| 个人记忆自动处理 | 自动整理记忆 | 关闭后不再整理，也不会在新请求中使用记忆；已有内容保留。 |
| Agent Bar 的单会话入口 | 会话总结 | 工具条与窗口标题统一。 |
| 已选会话的总结动作 | 总结此会话 / 生成总结 | 目标时间与来源正文始终可见。 |
| 会后结构化纪要 | 会话总结 | 栏目：主要内容、决定、待办、需要注意；分别映射概要、结论、待办、风险。 |
| 会话总结记忆参考偏好 | 总结时参考记忆 | 用已记住的信息补充背景，不会把总结自动记入记忆。 |
| 终态会话 | 已结束的会话 | 被中断时额外标明“会话中断，仅总结已保存内容”。 |
| 记忆候选 | 自动整理，待确认 | 不展示概率、semantic key 或内部 revision。 |
| 忘记 | 不再使用 | 操作旁说明“保留这条内容，但不再用于回答或总结”。 |
| 删除 | 删除这条记忆 | 明确说明删除对象，不暗示同时删除字幕历史。 |
| 正式 Agent 交互的高级详情 | 详细信息 | 模型、来源和导出；工具调用默认折叠。 |

术语映射用于所有可见文本、tooltip、aria-label、空状态和错误文案；代码/合同继续用规范术语。按钮必须有文字或可发现的文字标签，不能只给没有解释的图标。沿用语义 token、深浅主题、高对比、键盘焦点和 reduced motion，不引入新装饰动画。

### 3. 开关语义与默认值

新增全局 `summaryUseMemory`。首次安装或升级时缺失值默认为 true，让用户在开启 Agent 与个人记忆后可以直接得到带背景的总结；生成前明确显示本次会参考相关记忆，用户可以随时关闭。既有个人记忆和 Agent 总开关原值不改。

| Agent 总开关 | 自动整理记忆 | 总结时参考记忆 | 新后台摄取/综合 | 新总结 |
|---|---|---|---|---|
| 关 | 任意 | 任意 | 不创建 | 不生成，提示启用；既有结果可查看 |
| 开 | 关 | 任意 | 不创建 | 仅本次正文；说明记忆已暂停 |
| 开 | 开 | 关 | 按资格处理 | 仅本次正文 |
| 开 | 开 | 开 | 按资格处理 | 本次正文 + 有界相关个人记忆 |

“自动整理记忆”沿用现有休眠同时禁止读取的合同，因此不是一个只停后台、保留读取的新开关；说明必须写清。关闭总结参考不停止后台整理，也不意味着会话从此不被记忆处理。

新总结创建时由 main 冻结偏好、个人记忆处理状态及被允许的引用。普通偏好变更只影响之后新请求，自动重试沿用原绑定；忘记/删除/来源撤销优先于冻结快照，运行提交前复核并丢弃受影响结果，不能借冻结保留已撤销内容。旧总结的使用状态迁移为“未记录是否参考记忆”，不根据现设置倒推。

偏好关时，不仅移除提示中的记忆：冻结上下文、工具授权范围、route 输入、工具结果和模型 payload 都排除个人记忆、跨会话经历、记忆概览与其它会话正文。沿用 summary.minutes 的静态工具登记，search_context 只能返回允许范围内的结果，不动态修改相同 recipe/version 的工具授权。

开启但没有相关记忆时显示“未找到相关记忆，仅依据本次会话”；读取异常时不静默改变用户请求，提示“暂时无法读取记忆”，提供“重试”和“仅用本次会话生成”作为一次明确降级，不修改全局设置。结果用“已参考 N 条记忆”表示确实纳入模型输入的引用数，而不是模型必然采纳了每条内容。

### 4. 总结入口与可见反馈

工具条点击“会话总结”只打开/恢复/聚焦面板，不隐式发送模型请求；历史行“总结此会话”传递精确 session 身份，不擅自换成最新会话。工具条首次默认最近的合格终态会话并显示日期时间；正在监听时显示“当前会话还在进行，可选择已结束的会话”，不自动停止监听。

下一次可渲染帧呈现按下/打开反馈；main-owned 打开动作返回回执，renderer-ready 与窗口创建失败分离。5 秒未确认内容就绪显示“打开时间较长，可重试”，这是等待提示，不臆断失败或偷偷生成第二个窗口/任务。窗口销毁后允许重新打开；重复点击聚焦同一窗口；真正打开失败在工具条内显示“暂时无法打开会话总结，请重试”。

面板状态：
- 初次读取：“正在读取会话…”；不是没有数据。
- 没有会话：“还没有可总结的会话。开始监听并结束后，就能在这里生成总结。”
- 没有正文：“这次会话没有保存到字幕。”
- 缺模型：“先设置模型，才能生成总结” + “去设置”；保留会话选择。
- 已具备配置：“生成总结”；配置充分不宣称联网已验证。
- 运行：“正在生成总结…” + “取消”；不伪造百分比。
- 取消中：“正在取消…”；仅终态回执后显示“已取消”。
- 失败：“这次总结没有生成，请重试”；鉴权/网络等公开原因按闭集映射，保留上下文。
- 结果：时间、来源版本、正文栏目、记忆使用事实；“重新生成”建立新运行，不覆盖旧结果。

保留会话问答为次级“针对这次会话提问”，不扩展成通用聊天。问答沿用独立既有记忆信号规则，summaryUseMemory 只控制 summary.minutes；在输入旁说明“提问会按记忆设置使用信息”，避免把总结开关误认为所有 Agent 的开关。

### 5. 总结的只读边界

summary.minutes 请求、系统固定提示、结果与普通 edit/accept/reject 不触发 context.ingest.interaction；终态直接清理提示，不为“提取信号”延长保存。后台对原会话的 context.ingest.session 独立运行，不受此规则影响。

保留单独的“记住其中一条”：用户选定文本并明确提交到 manage/受治理信号入口，选择范围与类型后才写入；不把整篇总结默认当成用户事实。总结导出保存记忆使用事实和引用身份，追加 schema 版本；旧版本读取与相同旧交互重导出仍保持原有字节一致承诺。

### 6. 综合视图的模型与更新边界

个人记忆综合视图属于个人上下文模块的可重建派生投影，不等同于新增权威事实表或普通分析报告。保存有界 sections、每段 evidence refs、输入 revision/digest、模型绑定、更新时间、失效/省略信息。以当前有效会话经历记录和个人记忆重建；旧综合文本只能用于展示，不作为唯一递归模型输入。

新增静态 `context.synthesize@1`，模型用途为“摘要与总结”，最多 3 轮，工具授权为空；仍走同一个 Agent Loop 和十轴预算。首版只自动综合既有全局及已登记项目/主题范围；不自动建立项目归属，未知归属留在会话要点供查看。综合视图不得改变底层个人记忆的确认状态或写回其内容；用户纠正才经 manage 更新底层明确内容并触发重建。

建议初始应用上限：每范围每批最多 64 条经历 + 128 条个人记忆，累计输入正文 64 KiB，输出最多 12 节且 16 KiB；还必须满足所选模型及固定 recipe 更严格的预算。超量分页处理，每批冻结来源和游标，显示实际覆盖与省略；不截断条目正文，也不把部分范围写成“全部历史”。首版每范围保留当前与一个上版投影，更多历史沿用底层 revision，不无限保存综合正文。

资格成立的摄取/明确修改提交后推进范围 revision，30 秒内合并唤醒；每范围至多一个在运行及一个待处理目标 revision，全局综合并发为 1；下一轮从新目标读取。崩溃恢复走 scheduler 对账。技术故障不向 UI 暴露 scheduler 错误，公开投影仅说明“暂时无法更新，仍显示上次内容”。没有新来源/纠正时不重复请求模型。仅时间经过可将待办期限标为“日期已过，结果未确认”，不得写成已执行。

旧历史默认不补摄取。增加明确“整理以前的会话”流程：选择日期范围，预览来源数量及云端使用说明，再点击“开始整理”；分页、有界、可取消，遵守 suppression。此动作是明确授权的历史摄取，不修改自动处理边界；记忆休眠时提示先开启。首次打开设置页不得等同于授权。

来源删除、忘记、纠正与综合提交竞争时，用 expected revision + suppression 复核。隐私撤销事务先使受影响段及其上版投影不可读且不可检索，再异步重建；无关段保留。模型失败不能恢复被撤销的旧段。结果失效时不得继续把旧正文发往模型。

### 7. 文件与合同责任

- `personal-context` 对外仍只有 ingest/resolve/manage；投影视图读取与纠正在版本化 manage 命令中扩展，后台综合经受限内部 service 提交。
- `agent-run-service` 冻结总结偏好及输入，`agent-interaction-signal-service` 负责 minutes 信号排除；renderer 不决定实际读取政策。
- storage worker 单写者拥有投影、引用、幂等目标 revision 与历史输入身份；模型调用在事务之外，提交用短事务复核。
- main/preload 与 IPC access policy 同步增加 exact 请求/结果；不能透传自由 SQL、scope 查询或让 renderer 指定模型端点。
- 修改工具条打开回执时同时更新其 contract/fixture，保留既有角色权限；不通过改标题就宣布解决无反馈问题。

## Risks / Trade-offs

- [综合文本可能把推断写成事实] → 每段来源、明确内容优先、冲突单列、来源不可验证时拒绝输出；确定性 provider 只证明机制，实机还需人工审查质量。
- [普通用户不理解开关差异] → 两个分组各一行用途说明，结果页呈现实际输入，覆盖四种设置组合的真实 UI 旅程。
- [总结再次摄取形成循环] → minutes 专用信号排除及零写入联合断言；用户明确记住另计。
- [模型调用堆积影响字幕] → 合并、并发上限、固定预算、短事务、字幕提交 ACK 不等待后台。
- [需求与旧文档相冲突] → SEM-F37/F38 是本增量边界；旧 S5 总入口及 SEM-F32 通用信号以本次限定条款为准，其余规则保留。
- [修改正在进行的设置样式] → 本轮只追加规划；后续 renderer 落地依赖当前样式 change 的实际工作树，不能覆盖其输入控件修整。
