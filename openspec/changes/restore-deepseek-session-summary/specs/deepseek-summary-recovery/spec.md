## ADDED Requirements

### Requirement: 窗口内完整会话直接总结
系统 SHALL 以 256,000 token 为新总结运行的应用上下文目标，受模型实际能力约束并计入指令、完整输入、工具消息和输出预留；能够适配的完整输入交给既有 Agent Loop，超限明确拒绝且不截断。字节保护 SHALL 与输入目标协调，不能将 token 窗口误解为响应体 MiB。实施前 SHALL 在语义合同和旅程矩阵登记计数方式、实际字节上限与版本解释。

#### Scenario: 旧小上限不再阻挡窗口内输入
- **WHEN** 新建总结使用超过旧15,000字节且位于当前有效窗口内的合成会话，完整请求经计数适配模型与应用预算
- **THEN** 请求通过预检并包含完整冻结事件范围，不再因旧 15,000 字节门槛拒绝

#### Scenario: 输入超过有效窗口
- **WHEN** 完整请求加输出预留超过有效窗口或无法证明适配
- **THEN** 明确拒绝本次请求，不外发超限请求、不截断输入、不提交部分纪要

#### Scenario: 当前保守计数拒绝较大样本
- **WHEN** 173,827字节合成会话使用无受控tokenizer且注册输入轴120,000的策略
- **THEN** 预检明确拒绝，零总结模型调用，不将旧字节÷2公式作为适配证明

### Requirement: 受控 JSON 合同与独立输出额度
系统 SHALL 提供与 recipe exact validator 对齐的受控 JSON 指令和结构示例，并将单次输出目标 8,192 token 与模型能力、运行剩余输出预算及上下文余量取小值。模型能力配置 SHALL 保持原值，旧运行 SHALL 沿冻结版本和绑定解释。

#### Scenario: 正文不含 JSON 且模型输出能力较大
- **WHEN** 正文没有 JSON 字样、模型输出能力为 81920，剩余预算与上下文余量均充分
- **THEN** 正式请求仍含正确 JSON 指令和结果结构，max_tokens 为 8192；配置不被改写

#### Scenario: 继续旧运行
- **WHEN** 用户在重启后明确继续旧运行
- **THEN** 使用旧冻结绑定和预算，不借继续操作升级容量策略

#### Scenario: 工具后续轮与剩余输出额度
- **WHEN** 工具消息使完整请求增长，或已知输出余额减少
- **THEN** 每次外发前重算并拒绝超限；零输出余额零额外外发，usage未知不伪造为零消耗，模型能力不被修改

### Requirement: 失败与取消不提交纪要
系统 SHALL 复用现有校验、取消和事务屏障，对截断、空白、非法 JSON、Schema/来源错误准确失败；取消保持取消终态，迟到结果不得发布。工具调用中间消息 SHALL 不作为纪要。

#### Scenario: 截断或取消后收到结果
- **WHEN** provider 返回 length（即使 JSON 可解析），或结果在取消后迟到
- **THEN** 不提交纪要；保留对应失败或取消事实及无正文诊断

### Requirement: 正式路径验证
系统 SHALL 通过真实 Electron/main/preload/runtime/SQLite 旅程验证窗口内会话生成、保存、重开、取消和字幕独立，真实 DeepSeek 验证单独列证。

#### Scenario: 合法结果保存与重开
- **WHEN** 用户从正式应用生成窗口内会话总结并关闭重开
- **THEN** 可读取同一合法四栏纪要；取消或失败场景零纪要，下一字幕会话仍能独立运行

#### Scenario: 公网验证受阻
- **WHEN** 凭据或网络使真实 DeepSeek 验证无法执行
- **THEN** 记录实机范围未验证，连接测试和受控 provider 旅程不替代真实模型证据
