## ADDED Requirements

### Requirement: 本地诊断具有稳定关联和有界保留
系统 SHALL 按SEM-F40记录exact白名单元数据，关联受理请求、run、attempt和各阶段；按容量/期限滚动保留，诊断不作为任务权威或恢复来源。

#### Scenario: 输入在模型调用之前失败
- **WHEN** 输入预检或计划拒绝执行
- **THEN** 诊断记录阶段、稳定错误码及已知实际/限制指标，没有虚构模型调用或工具调用；十轴预算失败记录匹配的预算轴和单位，`summary.minutes@1` 的既有 15,000 UTF-8 字节兼容预检没有注册预算轴，故记录 `budgetAxis=null` 与 `bytes` 指标。

#### Scenario: 模型请求没有结束事件
- **WHEN** 请求外发后provider迟迟不响应或进程中断
- **THEN** 诊断保留开始事件及最后已知阶段，恢复快照说明未知/中断，不依据缺失日志推断成功。

### Requirement: 活动任务与终态均可主动导出诊断
系统 SHALL 提供独立的导出诊断入口，使用main-owned保存对话框、exact Schema校验与原子写；正文结果导出继续仅对终态开放。活动诊断是导出时点的有界观察，不承诺其后不变。

#### Scenario: 运行中导出与取消对话框
- **WHEN** 用户在等待模型时导出诊断，或取消保存对话框
- **THEN** 前者得到可解释的无正文诊断，后者零写入且不提示成功；导出不改变任务状态，目标路径不进入日志或SQLite。

### Requirement: 诊断隐私和故障隔离
系统 SHALL 禁止字幕、提示、工具参数/结果正文、模型中间文本、reasoning、凭据、音频、设备名、绝对路径及原始异常进入诊断。诊断写失败必须可见且内存有界，不阻塞任务终态和字幕。

#### Scenario: 敏感标记穿透扫描
- **WHEN** 受控字幕、提示、工具结果、异常及provider事件各带独特敏感标记
- **THEN** 所有诊断文件、诊断导出及证据JSON中均无标记/音频/路径/凭据；正式交互导出仍按SEM-F35独立验证。

#### Scenario: 日志目录不可写或达到保留上限
- **WHEN** 日志写入失败、文件数量/字节/年龄超过登记上限
- **THEN** 按策略清理或显示诊断记录不可用，内存不增长失控，SQLite任务状态和字幕历史仍可读取。
