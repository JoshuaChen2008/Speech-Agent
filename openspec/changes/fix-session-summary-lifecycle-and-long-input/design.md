## Context

本变更状态为「已决定」。需求/数值唯一权威是 [语义合同增量](../../../docs/semantic-contract.md#会话总结运行与长输入增量2026-09-27)，术语见 [CONTEXT](../../../CONTEXT.md)，架构裁决见 [ADR 0021](../../../docs/adr/0021-summary-lifecycle-and-long-input.md)。本文件解释实现边界，不宣称已有代码达到目标。

已确认的问题链：后台45ms内输入超预算失败 → main终态接线未通知 → UI保留running → 取消实际终态产生STATE_CONFLICT → 泛化为服务不可用 → 取消失败不刷新详情。已确认的输入大小为173,827字节/1,589段；不是模型生成持续418秒，也不能从零工具记录推导为检索未命中。

当前工作树已有路由关键词/执行宿主导出修复和其它任务改动。本变更不回滚或复写这些变更，不把它们计为自身任务。`clarify-memory-and-session-summary` 负责既有记忆设置与单会话入口；本变更接续运行闭环和长输入。runtime-architecture §11.3 的旧 PluginHost/三项自动任务/环境凭据段落是已识别历史缺口，不作为新实现模板。

## Goals / Non-Goals

**Goals:** 状态可信；从提交至终态可取消；可定位失败阶段；4–5小时输入完整覆盖；模型和内存预算有界；字幕独立；旧绑定/导出兼容；其它任务有稳定语义入口。

**Non-Goals:** 不保存现场音频，不显示或留存模型内部思维过程，不增加动态工具或子Agent，不安装新Agent框架，不自动换模型，不恢复中间正文，不扩容问答/个人上下文摄取，不承诺任意时长或任意模型的生成质量。运行反馈优先使用宿主真实阶段，SSE token流不是本次前置条件。

## Decisions

### 1. 分三片交付，现有故障先恢复可信状态

| 切片 | 范围 | 独立退出条件 |
|---|---|---|
| P0 | 终态广播、详情校准、取消终态幂等、准确错误与预算预检 | J30-STATE/CANCEL 和 J31-SIZE 的短输入/现有上限路径成立；仍不得宣称长输入已支持 |
| P1 | 受理身份、路由取消、阶段快照、期限/租约、诊断导出 | J30全矩阵；运行中及失败后用户能定位问题 |
| P2 | v2策略、完整分块/归并、受限分页、全量重跑、长输入旅程 | J31全矩阵、旧版本兼容及字幕独立；真实五小时与模型质量另验 |

每片先补行为回归再改实现；所有新增语义已经登记，实施者仍须在任务回执中逐条引用SEM/gate。

### 2. 请求身份先于模型请求

新增只含元数据的受理记录，由 storage worker 唯一写入，逻辑字段为 requestId/clientKeyDigest/requestDigest/scopeDigest/promptDigest、动作、冻结记忆政策、可空routeRunId/targetRunId、state/revision/generation、cancelRequested、相对时间累计。用户文本留在既有受控提示内存中，终态清理；不新增持久提示正文。明确总结的固定提示可由版本重建，自然语言问题在重启后若提示已丢失，明确要求重新提交，不能空提示自动恢复；重新提交期间固定原会话范围，新问题成功受理时通过同一存储事务清除旧问题的待重新提交标记。

renderer 提交闭集 action=summary 或 question；禁止提交任意recipe/provider/预算。保留旧IPC版本消费者，新增exact合同版本并同步fixture、access policy、preload、service、renderer。提交回执先返回requestId；即使target run尚未创建，也能查询和取消。未知提交结果保留同一幂等键，重试收敛到已受理请求。明显重复点击锁住同一请求；活动请求期间生成按钮禁用，不能因submit Promise结束就重新放开。

明确summary动作零模型路由；question动作保留模型优先+规则兜底。受理取消原子阻止新目标run，路由迟到成功不能创建目标。路由与目标用同一请求关联诊断，但不向用户暴露intent.route。

### 3. 状态由事务事实驱动

结果写入、run终态及快照revision在storage事务中收束。广播必须在提交后，且不能依赖可失败的记忆信号处理/提示清理。后台成功、失败、取消、重试等待、恢复都走同一通知出口；通知丢失不破坏重新查询。

Agent运行快照的exact投影包含请求/run身份、attempt、generation、revision、state、phase、elapsedMs、lastActivityAgeMs、块计数和可空错误/预算说明。created/terminal时间继续遵循已有结果合同；诊断只用相对时间。UI本地秒表仅用于“已等待”，不递增revision、不更新最近模型活动。一个attempt内块进度单调；重跑明确重置并显示attempt，不能沿用旧百分比。

读取绑定目标身份和代次，旧会话/旧interaction/旧请求的响应不得覆盖新选择；同一在途详情读取不重叠，迟到读取不能覆盖更新revision。轮询不反复拉整场正文或全历史，不覆盖反馈草稿。空结果与读取失败分别呈现。

### 4. 取消、期限和租约

取消入口先向当前controller发信号，并独立提交持久取消请求；不等待模型响应才处理控制命令。提交事务同时检查取消、owner、attempt和冻结输入。成功先提交则取消回执返回succeeded；取消先登记则任何迟到成功拒绝；失败先提交则返回原失败，附原错误说明。

外部请求使用AbortSignal与宿主Promise期限双重收束；abort不合作的promise仍挂接拒绝处理，失效attempt不再写工具/结果。失去租约时停止新外发/提交；续租不作为模型活动。同步CPU工作分批让出事件循环，取消检查覆盖分页、序列化、分块、归并；若迁入专用执行worker，只管理准确child，不触碰字幕/audio/storage进程。不能依靠同一被阻塞事件循环上的timer声称满足取消期限。

取消落库失败时保留“状态尚未确认”，只读对账并允许重发同一取消；不能谎报已取消。关闭总结窗口不隐式取消，重新打开读同一请求；应用退出有界停止Agent，重启将未终态总结等待用户明确继续。以retry_wait加resume_required原因投影，不扩充旧run状态CHECK；scheduler领取谓词必须拒绝尚未明确继续的运行。

新attempt整次重跑并复用绑定，累计预算不因进程重启清零。实际请求数在外发前持久预留，attempt在领取事务中计数；相对执行时长随续租结算，未结算崩溃区间按已预留租约时间保守计入并单独标记，不能靠反复退出绕过期限。准确provider用量未知时不补造；不能确定剩余控制预算时拒绝恢复。来源删除/记忆撤销/凭据退休必须先失败，不能继续。

### 5. 一次总结，一个绑定，一个完整输入计划

`summary.minutes@2` 仍使用同一recipe ID和静态工具集；通过ADR 0021明确每个计划节点调用同一AgentLoopExecutor。旧`getRecipe`/输出schema/预算validator中硬编码version=1的路径要全部盘点，不能只在runner换字符串。v2可沿用最终栏目形状，计划和覆盖作为新交互元数据而非混入正文。

规划分两步：预检用catalog非敏感能力和流式计数给用户容量解释；创建run并bind后，用不可变绑定重新规划和验证，配置在两步间变化不能绕过限制。预检失败是请求可见终态，零总结模型调用；不改变现有处理资格ready的“配置充分”含义，而单独展示容量检查状态，检查期间禁止外发。

从个人上下文模块的字幕上下文适配器取得冻结的raw keyset分页。按首次稳定转写event_order排序，对每段登记覆盖范围；`segments.text`不得作为原始来源。单段超预算按code point范围读取/切分，包含JSON转义后的实际字节数，不能只按字符数估算。所有片段的有序并集恰等于冻结输入且无缺口/重叠；planDigest绑定输入digest、模型绑定digest、policyVersion和全部范围摘要。

单次输入规划包含system/user提示、JSON envelope、允许的记忆上下文/工具声明、工具返回预留和输出余量。有受控精确tokenizer用精确计数，否则使用保守字节单位；真实模型拒绝上下文长度时明确失败或在原预登记预算允许下整次重新规划，不偷改冻结策略。不能因用户声明大窗口而跳过实际HTTP/内存上限。

确定性多层归并按连续块顺序、固定扇入进行，包含单块退化情况。归并至少要装得下两个最大受限中间结果及envelope，否则计划拒绝。中间输出采用exact结构化schema，字段含概要/结论/待办/风险和当前允许的来源引用；不保存自由assistant文本或reasoning。超出中间结果大小/条目容量必须失败，不截断数组。仅保留当前层必要结果、消费后释放；所有节点共享attempt工具预算及run用量累计。

全部节点成功并经覆盖证明、输出Schema、记忆政策、来源撤销和输入digest复核，才以一次幂等事务发布一个纪要。正文中同一事项的修订/撤回应保留时间顺序，末段修订不能被前段结论覆盖。覆盖校验是机械保证，语义准确度另以内容测试与实机评估验证。

### 6. 数据、合同和预算兼容

新增迁移只追加：受理元数据、run策略/输入计划摘要、运行快照所需相对累计/修订。具体migration版本在实施前按当时最新schema顺延；不得占用其它在途任务版本。现有v1绑定JSON逐字节不变，按recipeVersion/policyVersion分别校验。新代码读取旧行无元数据时显示未记录，不补造阶段/记忆命中。

计划只落摘要/digest/计数/预算版本；不落分块正文、中间模型结果、完整输入副本。重启重建计划并比较digest，配置修改不改既有绑定。SQLite终态/attempt历史和工具审计保留；诊断滚动清理不能删除这些事实。会话/交互删除需一并删除受理/计划映射；旧请求重放只返回已删除，不复活任务。

十轴仍在budget-axes模块集中定义；v1逻辑保留，v2通过策略标识解释作用域。对所有层实施统一核对：runner prompt、AgentLoop assertPrompt、模型runtime、adapter的16KiB字段/512KiB HTTP、工具audit、IPC协议、SQLite结果schema与导出validator。旧固定值只在仍使用旧策略的调用中保留。真实用量缺失时为null，已知部分只能保留为诊断计数，不能当完整run用量展示；更高内存/字节/调用次数上界仍执法。

### 7. 诊断与用户表面

采用本地受控schema滚动日志，归属main诊断服务；成功、失败、取消都记录终态事件，输入预检失败记录实际值/限制值/轴，不记录正文。查询仅按请求/run摘要和有界分页，renderer不能指定路径。诊断不可用有独立可见标记，不能覆盖任务真实失败原因。

UI主区显示会话、当前阶段、已用时、实际分块进度、取消/终态动作；详情折叠中显示诊断摘要和导出。等待模型时可以显示“等待模型响应，已等待…”，没有首token事件就不声称已开始输出。记忆状态按未读取/查询空/实际引用/读取失败分别表达。结果导出和诊断导出明确命名区分。

### 8. 开源实践采用范围

- [Vercel AI SDK停止流](https://ai-sdk.dev/docs/advanced/stopping-streams)：借鉴AbortSignal贯穿与独立取消收尾，不引入SDK替换现有模型接入层。
- [LangGraph streaming](https://docs.langchain.com/oss/javascript/langgraph/streaming)：借鉴步骤事件与文本流分离，不照搬持久化完整图状态，因为ADR0009禁止中间正文落库。
- [OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/)：借鉴同一运行关联阶段/相对耗时/错误，使用本地白名单schema，不部署遥测后端或自动上传。

## Risks / Trade-offs

- 长会话字节多、段短且密集 → 分别验字节/段数/请求数，不把五小时时长当唯一门槛；超出上界明确拒绝。
- 归并会丢失语义细节 → 首中尾哨兵、跨块修订/否定/待办/多语言测试；完整覆盖不宣传成无遗漏事实。
- 重启整次重跑有额外模型消耗 → 明确继续、有限attempt、旧绑定与剩余预算固定；不自动重试确定性超限。
- 大JSON/SQLite读取阻塞取消或字幕 → 有界分页、分批让出执行、控制路径优先；正式Electron并发字幕旅程和实机时延测量。
- provider不配合取消 → 本地期限、代次与提交屏障保证本地停止；不承诺服务端撤销。
- 诊断写满/权限故障 → 有界内存和清理，可见降级，任务权威与字幕不依赖日志。

## Migration Plan

先P0修复并保留旧预算；P1引入新exact合同和追加元数据迁移；P2登记并仅对新总结启用v2。保留v1解释器、旧导出编码器，已存在running v1在重启按原版本恢复/收束，不升级同一run。每片独立回归，P2只在J31成立后才能标记长输入实现完成·尚未验收。

回退为停止创建v2新运行、保留所有元数据及历史读取、显式收束活动v2；不删除新表、不回写旧迁移、不用旧程序猜读新运行。数据库回退如有需要只能按原备份流程，不能覆盖运行中的用户数据库。

## Open Questions

无阻止实施的产品选择。数值已有权威初始策略；实施时需测量首屏/取消/main延迟、峰值缓冲、真实模型质量和五小时长稳。若目标无法满足，记录实测并先修订SEM/策略版本，不能静默缩小容量或标记验收。未来中间结果持久恢复与SSE细粒度进展分别留作独立变更。
