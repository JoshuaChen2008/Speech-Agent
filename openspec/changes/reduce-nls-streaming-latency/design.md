## Context

需求是持续说话时尽快看到当前内容。用户不接受以旧规划中的 800ms 或本地沿用的 1000ms 作为云端优化终点。本轮只规划；证据与限制见 [research.md](research.md)。

现行路径：AudioWorklet 100ms 装帧 → audio-host renderer/FrameFlow → realtime worker/CloudAudioBuffer → main NLS 发送队列 → 公网 NLS → main router/Coordinator → caption renderer。已复现发送队列的持续积压，但实际触发来源未测得。

现行 SEM/ADR 冻结了 100ms 分片、上海网关、800ms 断句和 `<1000ms` 云端首个 partial 口径。本 change 拟调整它们，实施前先在 CONTEXT、语义合同、J20/I2 和 ADR 中登记；规划不自动改变既有验收结果。

## Goals / Non-Goals

**Goals:**

- 连续说话时内容及时更新；短暂阻塞后快速恢复跟随，避免长期保留几百毫秒到秒级欠账。
- 分别降低首字、持续文字更新、断句定稿和开始监听的等待，任何一项均不得冒充另一项。
- 用同机同项目基线确定当前可达到的最低延迟，保留准确性、可读性、连续性与资源证据。
- 产品内部可控制的额外等待优先消除；通过数据决定分片、发送恢复和网关，不预先承诺供应商端到端数值。

**Non-Goals:**

- 本轮不实施、不换 ASR 服务，不并跑云端与本地争抢正文，不改变纯本地质量/延迟门槛。
- 不落盘现场音频，不以丢帧、吞字、反复重连或让 partial 升格为 final 来制造低延迟。
- 不把所有实验参数暴露为用户设置；产品默认值由实验筛选，实验入口与生产入口隔离。

## Decisions

### 1. 先测什么，再改什么

P0 构建专属云端诊断入口，使用正式 RecognitionRuntimeAdapter 与 renderer，不复用本地 I2 结果。先冻结受控语料及词/短语锚点、主要语种和长短句组合；音频在内存中提供，报告保留语料/配置/版本哈希。把读指标本身的开销做探针开/关对照。

| 测量 | 方法与解释边界 |
|---|---|
| 首个 partial | 保留受控语音起点到 Coordinator 接受事件的旧测量；另记录 renderer 应用与下一绘制机会。rAF 不是实际像素显示证明 |
| 持续文字落后 | 受控语料冻结词/短语结束时刻，内存匹配首次显示该锚点、以及保持至首次稳定转写的时刻；漏识别计覆盖失败，不从统计中删除 |
| 持续更新间隔 | 已知有语音区间内的有效正文修订间隔与最长停滞；重复相同正文不算改善。静音区间单列 |
| 帧年龄与排队 | 帧样本末端 → host/worker/main 到达 → socket 入队与本地发送 callback，区间分别记录；callback 不是服务端接收确认 |
| 服务回传 | 以样本映射记录结果回传时的已发送/已处理音频水位；`payload.time` 不是正确文字跟随性的替代指标 |
| 积压恢复 | 可重复 100/300/600/1200ms 停顿后，待发音频回到无停顿基线一个帧时长以内所需时间；连续采集时测，不等停止后排空 |
| 定稿与启动 | 受控发音结束到 SentenceEnd；点击开始到监听就绪、就绪后首字分开，不提前秘密采集 |

各段保留 P50/P95/P99、max、计数与缺失数；稀有阻塞按受控事件窗口记录，不能只看整场 eventLoopP95。跨时钟域复用现有校准，时钟偏移/绝对时刻只在内存，校准质量不足标记未知，禁止将负值钳成零伪造闭合。云端任务恢复时将 task 音频轴与 session 暂停间隔显式映射。

P0 先登记这些测量在 CONTEXT 的准确含义与报告白名单，再写诊断代码。报告不保存正文、逐词内容、音频/设备/本地路径、凭据和原始网络帧。

### 2. 云端验收采用体验向量与同机对照

800ms/1000ms 不作为候选达到后停止的条件，也不通过放宽数值抹去历史失败。纯本地冻结口径保持；云端保留同起点测量用于历史比较，并另登记持续跟随、最长停滞、恢复、定稿、准确性和资源边界。

实验流程：同一项目/语料/来源/网络窗口交错运行基线与候选，每项候选先至少 5 个配对轮次，再对入选方案做 30 分钟连续语音与停顿组合；发布仍走适用 I3 两小时。来源分别测，不并发采集。运行顺序冻结，候选不得挑掉慢轮；失败轮留在分母。参考程序仅有 UI 观察时，单独注明人工观察，不能当作同精度仪表化数据。

选择规则：准确性与连续性不得退步；优先减少持续文字落后的尾部和最长停滞，其次减少积压恢复时间与首字，再比较定稿/资源。明显的冲突保留多方案比较，不把单一平均值做成总分。P0 基线之后、候选结果揭盲之前，登记测量误差、最小有意义差异与质量容差；当前不虚构这些实机数字。筛选量表不是无限迭代目标：本计划的有限矩阵均有结果，入选组合真实复验，剩余成本/边界写清，即可结束本轮；不能声称达到物理极限。

### 3. P1：发送队列是首个优化对象

真实采集到帧后优先立即提交 socket，保持发送顺序与本地背压；只有出现积压、socket 拥塞或会超过已登记的突发预算时才调度等待。对照现行累计期限算法；不在正常每帧后再人为增加固定等待。

恢复候选先比较小额突发预算和 1.25×/1.5× 有界追平，不代表供应商已批准这些速度。若真实服务不支持，拒绝候选；不能用取消所有等待的诊断对照直接上线。以音频毫秒计预算，单次同步工作量和任意滑动窗口突发量都有限，持续网络受阻仍在 2 秒上限内显式失败。

推导用于解释收益：积压 B、采集速率 1、有效发送速率 r>1 时，理想恢复时间 B/(r−1)。600ms 积压在 1.25× 下约 2400ms、1.5× 下约 1200ms；r=1 永远追不平。这不是实测，提醒不要把“采用追平”误当“恢复很快”。

失败矩阵包含连续定时迟到、长阻塞、写 callback 延迟、socket bufferedAmount 增长、暂停/停止期间排空、取消与迟到 ack。保留现有 60 秒留存、2 秒待发、唯一首次稳定转写和单向本地降级规则。另明确统计 capture 端 FrameFlow 的积压，不能让排队从 main 移到上游后看起来变低。

### 4. P2：100/40/20ms 分帧独立比较

只对云端采集链路实验：100ms=1600 samples、40ms=640、20ms=320，均为 16kHz 单声道 PCM16。正常情况下单样本平均装帧等待由约 50ms 降到 20/10ms；这是均匀到达假设下的理论值，100→20ms 不能承诺总延迟减少几百毫秒。

不能只在 main 将已经形成的 100ms 帧拆小，那样不减少采集等待。需从 worklet 的装帧设置贯通 host、worker、provider；credit 窗口与队列以时长核对，不能无意把 2 个 credit 的覆盖从 200ms 缩成 40ms 后引入新停顿。

本地 core 有按帧数计的 pre-roll/provisional/段长逻辑。纯本地继续 100ms；云端降级时从精确已提交样本边界将小帧重组为本地 100ms 输入，保留样本连续性、尾帧和时间轴，不能改变 VAD 参数或让新分片把原有上限缩小五倍。只有测得明显 GC/CPU 成本，才进一步优化 FrameAssembler 的数组复制；不先做无证据的环形缓冲重写。

### 5. P3：网关和识别参数分别验证

- 网关：先同一参数比较当前上海与官方就近域名，参考旧域名可作为诊断对照；固定 allowlist，禁止任意 URL、重定向或运行中悄悄换网关。验证项目/Token/header 的地域兼容、实际 ASR、质量和持续连接。无鉴权 HEAD 结果不能决定上线。
- 断句：800/500/300ms 单变量比较，测定稿、段切换、短停顿/中英文准确性与段碎片化。参考配置 300 只是候选依据，未证明旧程序实际请求就是 300ms。
- 标点：固定其它参数比较开/关，测持续 partial 与首次稳定转写质量。若无稳定收益就保留现状。ITN/语义断句当前已关闭，不重复列为“新增优化”。
- 参数需由会话冻结绑定传到实际请求；当前 provider 直接导入 NLS_PARAMETERS，不能只改设置快照却仍发旧参数。

### 6. P4：只有分段证据支持才改架构

若在交互/Agent 活动时，main 入队到发送或接收处理占主要尾部成本，比较隔离识别网络调度的执行位置。迁移 WebSocket 会触及 ADR 0020 的 main 凭据所有权与退出边界，必须单独登记，不能直接把密钥交给现有音频 worker。

若 worklet 之前已存在主要持续延迟，才研究低延迟 WASAPI 采集与 Chromium 来源设置；先取得同机采集年龄对照，再决定是否值得承担原生模块、设备恢复和打包成本。若 renderer 是主要成本，先优化真实局部布局/调度，不制造未识别文字或“打字机效果”。

## Risks / Trade-offs

- 小帧提高 IPC/网络包数量 → 测消息数、CPU、GC、队列尾部和丢帧，选最小稳定成本点。
- 有界追平可能增加服务端排队 → 同时看 socket 排队与结果水位，真实 NLS 拒绝或无收益就淘汰。
- 降断句可能使语义破碎 → 以质量/漏字与定稿收益共同决定，不用 partial 首字改善掩盖质量损失。
- reference 文档并非源码事实 → 保存证据等级，实际请求/采集大小未知就保留未知。
- 只测首个 partial 会漏持续落后，事件采样会低估长空窗 → 固定语音锚点、最长停滞和覆盖度共同报告。
- 改参数可能破坏历史读取 → 先历史版本兼容，后变更默认值。

## Migration Plan

1. 按存储路由审查旧识别绑定；无版本的旧绑定按固定旧形状解释，不能依赖当前默认常量。新绑定登记请求参数、传输策略版本和网关策略身份，不把非 NLS 字段塞入请求 payload。
2. 新版本校验器同时接受受控旧/新形状，未知版本拒绝。若确需 schema 变更只追加 migration，历史 SQL/checksum 不改。region 不能将就近路由虚标为上海。
3. 实验在隔离数据目录使用已授权配置入口；不读写用户历史做试验。入选参数只影响新会话；暂停恢复/本地降级遵循本会话冻结策略。
4. 回滚新默认到旧策略需保留新历史读取能力；不把可执行程序降回不理解新绑定的旧版作为无条件回滚。

## Open Questions

- 用户实机积压首次产生在哪一段，以及当前主来源、语种、典型连续讲话长度；可由受控复现与当前会话非敏感配置收集。
- 参考程序 300 字段的真实 NLS 映射、分帧与文字更新节奏；原版不保存现场音频的前提下补对照。
- 同项目就近域名是否接受当前 header/Token，实际识别延迟和质量是否改善。
- 追平速率、突发预算、质量容差与体验最小有意义差异由 P0/P1 实测决定，未确定前不推广默认值。
