## ADDED Requirements

### Requirement: 统一产品操作与持久受理
操作层 SHALL 接受闭集动作、受限输入、范围和幂等键，组织冻结输入与模型运行绑定；模型请求前形成并向调用者提供持久受理身份，renderer 不指定厂商 URL、凭据、任意 recipe 或预算。

#### Scenario: 提交回执丢失
- **WHEN** 调用者用同一幂等键再次查询或提交同一请求
- **THEN** 返回同一持久请求身份，不建立重复运行或额外模型请求

### Requirement: 权威快照校准
操作层 SHALL 以 SQLite 为持久权威，事件仅加速刷新；UI 使用运行身份、revision 和 generation 校准 Agent 运行快照。

#### Scenario: 重开窗口并收到旧事件
- **WHEN** 运行期间关闭并重开 Agent 窗口，通知丢失或旧事件迟到
- **THEN** 读取同一请求的权威快照，拒绝旧身份/修订覆盖；关闭窗口不隐式取消

### Requirement: 取消与原子终态
操作层 SHALL 保留取消请求、信号与持久终态竞争规则，无法确认取消时展示未确认；合法结果和成功状态同事务提交。

#### Scenario: 取消落库失败
- **WHEN** 取消信号已发送但持久请求不能确认
- **THEN** UI 不宣称持久取消成立，后续通过快照核对终态；迟到内存事件不能覆盖已提交事实

### Requirement: 显式恢复与输入差异
操作层 SHALL 在重启后等待用户明确继续，保持既有预设动作与自由问题的恢复政策，不自动外发或新增原始提示持久副本。

#### Scenario: 预设动作恢复
- **WHEN** 中断的会话总结在重启后由用户明确继续
- **THEN** 继续前零模型调用；继续时使用同一运行的冻结输入、模型绑定与剩余预算，创建符合原政策的新 attempt

#### Scenario: 自由问题需要重新输入
- **WHEN** 中断的自由问题按既有政策要求用户重新输入
- **THEN** 界面明确提示并沿用原有重输流程，不能从不存在的原始提示副本自动恢复

### Requirement: 字幕独立与诊断隔离
操作层 SHALL 保持 Agent 缺席或故障期间字幕系统独立运行；诊断仅含允许指标与哈希，正式 Agent 交互导出保持独立的既有合同。

#### Scenario: Agent 等待期间诊断失败
- **WHEN** Agent 等待或取消期间诊断写入失败，用户启动下一字幕会话
- **THEN** 字幕仍能开始、停止、保存和查看历史，诊断故障不改写 Agent 产物终态，也不产生现场音频产物
